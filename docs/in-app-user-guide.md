## 범위와 화면 흐름

접속한 팀에서 상단 **사용 가이드**를 누르면 현재 로그인 권한에 맞는 설명을 바로 연다.

| 접속 상태 | 열리는 가이드 |
| --- | --- |
| 활성 팀의 감독·코치 개인 계정 | 운영진용 10개 항목 |
| 회원 계정·팀 코드 조회 접속 | 회원용 4개 항목 |
| 서비스 관리자이지만 현재 팀 감독·코치가 아닌 계정 | 회원용 |
| 로그인 전 또는 팀 미선택 | 기존 접속·팀 선택 흐름을 먼저 진행 |

선수 명단의 직책이 아니라 기존 `canEditTeam` 권한 판정을 사용한다. 가이드 표시는 읽기 안내이며 서버의 수정 권한을 바꾸지 않는다.

1. 선수단·경기 기록·선수 기록 옆의 **사용 가이드**를 누른다. 편집 중이면 기존 이동 확인을 거친다.
2. 운영진용 또는 회원용 제목과 가이드 버전·대상 기능판을 확인한다.
3. PC는 왼쪽 목차, 휴대폰은 목차 선택 상자로 한 항목씩 읽는다. 아래 이전·다음으로도 이동한다. 항목 변경 시 제목으로 포커스와 스크롤을 옮긴다.
4. **PDF 내려받기**로 같은 역할의 공유본을 받는다. 페이지에 있는 공개 접속 주소는 새 탭으로 열린다.
5. 다른 업무 메뉴로 돌아갈 수 있다. `#guide` 직접 접속·새로고침도 같은 권한 판정을 사용한다.

![가상 검증팀의 모바일 운영진 가이드](diagrams/in-app-user-guide-mobile.png)

위 그림은 최초 로컬 구현 때 촬영한 가상 계정 화면이다. 운영 서비스와 실제 회원 정보를 포함하지 않으며, 현재 가이드 1.1의 항목 수와 본문은 아래 공통 원본을 기준으로 한다.

## 원본과 빌드

- `docs/guides/content.json`을 React 화면과 HTML/PDF 생성기가 함께 사용한다. 앱 화면용 원고를 따로 복사하지 않는다.
- React는 `<b>` 강조와 `<br/>` 줄바꿈만 지원하고 나머지는 텍스트로 처리한다. HTML 직접 삽입은 사용하지 않는다.
- 공유 PDF는 `?url` 정적 import로 빌드에 포함한다. 파일 변경 시 Vite가 새 자산 이름을 생성한다.
- Docker의 프론트 빌드에도 JSON과 두 PDF를 복사한다. `.dockerignore`에는 필요한 세 파일만 허용한다.
- 현재 원고 1.1은 회원용 4쪽·운영진용 10쪽이다. 시즌 선수 기록, 6종 포메이션과 새 선호 포지션, 02·03 한눈에 보기, 경기 초안 복원·저장 결과 확인을 포함한다. [가이드 갱신 기록](guides/maintenance.json)에 반영 기능과 실제 배포 상태를 남긴다.
- 앱 가이드는 빌드에 포함되므로 다음 기능 배포 때 가이드 변경도 함께 준비·빌드한다. 운영용 가이드의 최종 기준 버전과 배포 완료 표시는 실제 배포 확인 후 확정한다. 이번 확정 작업에서는 배포된 화면 본문·기능판 표시·PDF·역할별 HTML을 다시 생성하거나 변경하지 않았다.

## 인수 기준

- 감독·코치에게 운영진용, 코드 접속·회원에게 회원용을 자동 표시한다.
- 역할이나 팀이 바뀌면 이전 역할에서 읽던 항목을 그대로 남기지 않는다.
- 작은 화면에서도 가로 넘침 없이 읽고, 목차·이전/다음·다운로드를 누를 수 있다.
- 편집 중 가이드 이동은 기존 초안 보호를 유지한다.
- 내려받은 PDF와 저장소의 역할별 PDF가 같다.
