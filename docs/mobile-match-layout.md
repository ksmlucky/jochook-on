# 경기 기록 모바일 화면 개선

## 범위와 화면 흐름

- 기본 정보: iOS 날짜 입력의 기본 최소 너비 때문에 영역을 넘지 않도록 너비·최소 너비를 명시한다. 날짜 선택 기능은 유지한다.
- 01 투표·출석: 참석 선수 선택 카드도 360~700px에서 4열, 360px 미만에서는 3열로 표시한다. 간격은 6px이며 등번호·이름·포지션·연령대를 줄로 구분한다. 카드 전체를 눌러 선택하며 우측 위 체크와 선택 배경색으로 상태를 표시한다. 검색, 선택한 선수만 보기, 실제 출석과의 구분은 유지한다.
- 02 스쿼드 계획: 360~700px에서 후보 선수를 4열, 360px 미만의 매우 좁은 화면에서는 3열로 보여준다. 카드 사이 간격은 6px이다. 모바일에서 등번호와 이름을 위아래로 나눠 이름 읽을 공간을 확보하고 선호 포지션, 연령대, 현재 배치와 총 출전량을 유지한다. 후보 선택 → 자리 탭으로 배치할 수 있고 목록을 세로로 스크롤할 수 있다.
- 02 포메이션: 4-1-2-3 작전판으로 배치한다. 선발은 최소 50px, 배치된 교체는 최소 36px 높이를 사용하며 긴 이름은 줄바꿈한다. 빈 교체 자리는 선발이 있을 때만 높이 28px의 작은 ‘+ 교체’ 버튼으로 표시한다. 선수가 배치되면 교체 카드로 펼치고 해제하면 다시 작은 버튼이 된다. 조회 권한에서는 빈 교체 버튼을 숨긴다. 제거 버튼과 교체 출전량 계산은 유지한다.
- 03 실제 출전: 모바일에서는 포메이션에 선수·골·도움을 요약한다. 카드를 누르면 해당 자리의 선발·교체·골·도움 입력창을 연다. 입력창은 키보드 포커스를 가두는 기본 dialog를 사용하며 닫기 또는 Escape로 돌아온다. 입력 완료는 화면 초안에 반영하며 DB 저장은 단계별 저장 또는 중간 저장 버튼으로 한다.
- PC에서는 기존의 바로 입력하는 카드 형태를 유지한다. A/B팀, 1~4쿼터, 감독·코치 수정 권한과 회원 조회 권한을 그대로 사용한다.

## 인수 기준

- 375 / 390 / 430px에서 날짜와 포메이션이 가로로 넘치지 않는다.
- 375 / 390 / 430px 후보 카드는 4열이며 교체 자리는 선발보다 작다. 수비 4명은 풀백을 조금 앞으로, 센터백을 뒤로 두며 카드끼리 겹치지 않는다.
- 03에서 선발·교체 선택과 골·도움을 수정하고 창을 닫아도 초안에 유지된다. 입력창의 글자는 16px 이상, 입력 높이는 44px 이상이다.
- 쿼터·A/B팀 전환과 PC 화면에서 기존 배치를 유지한다.
- 운영 배포와 실제 DB 수정 없이 가상 데이터로 미리본다. 실제 iPhone Safari 확인은 사용자가 임시 주소에서 수행한다.

## 임시 미리보기

`work/mobile-layout-preview.mjs`는 빌드된 공개 프론트 파일과 가상 선수·경기만 제공한다. 실제 API로 프록시하지 않고 저장 요청을 거절한다. 비밀번호 없이 화면을 확인하며 새로고침하면 입력을 초기화한다. 임시 터널은 이 서버의 5192 포트에만 연결한다. PC 또는 미리보기 프로세스가 꺼지면 접속이 종료된다. 개발 서버 5173이나 실제 DB/API 포트는 공개하지 않는다.

## 작전판 배치 보완

사용자가 제공한 축구 게임 화면처럼 위치 간 공간을 구분한다. 선수 카드는 둥근 네모를 유지하고, 구장 경계·센터서클·하프라인·페널티박스를 배경에 그린다. ST를 가장 앞에, LW/RW를 양옆 조금 아래에, CM 두 명을 넓게, CDM을 중앙에, 풀백과 센터백의 높이를 다르게 둔다. GK는 골문 앞에 둔다. 02와 03은 같은 좌표 체계를 사용한다.

고정 픽셀 좌표 대신 CSS Grid의 칸을 사용한다. 교체 선수나 긴 이름 때문에 카드가 커지면 행 높이도 늘어나 아래 카드와 겹치지 않는다. 장식 선은 클릭을 받지 않고 보조 기술에서 숨긴다. 배치·교체·득점·저장 로직은 그대로다.

## 검증 기록 (2026-10-14)

- 프론트 기존 테스트 41개 통과, 최종 TypeScript 검사와 Vite 빌드 통과.
- Chromium 기반 모바일 크기 375 / 390 / 430px에서 날짜 너비, 후보 3·4열, 가로 넘침을 확인했다. 1280px에서는 기존 직접 입력 카드를 유지했다.
- 모바일 후보 선택 → 교체 자리 배치, 실제 출전 골 수정·교체 추가·도움 수정·각 0.5쿼터 표시를 확인했다. 입력창 닫기와 Escape 후 포커스 복귀도 확인했다.
- 자체전 B팀 상세 입력창에서 A팀 선수 선택 금지가 유지됐다.
- 작전판은 일반 출전과 4쿼터 교체·긴 용병 이름 사례에서 카드 사각형끼리 겹치지 않음을 확인했다.
- Cloudflare 임시 주소에서 가상 경기 3건 조회, 비공개 경로 404, 변경 요청 405를 확인했다.
- 이 작업에서는 백엔드·MySQL 통합 테스트 및 실제 iPhone Safari 기기 검증을 수행하지 않았다. 운영 배포와 Git push도 수행하지 않았다.

## 4열 후보와 작은 교체 버튼 확인 (2026-10-15)

- 375 / 390 / 430px에서 후보가 4열, 간격 6px로 표시되고 가로 넘침이 없음을 확인했다. 390px의 후보 너비는 66.5px이다. 등번호·이름은 별도 줄, 포지션 약어는 중간에서 끊지 않는다.
- 빈 교체 버튼 높이 28px, 선수 배치 후 선발·교체 각각 0.5Q, 해제 후 작은 버튼과 선발 1Q 복귀를 확인했다. 선발 해제 시 빈 교체 버튼이 사라지고 선발을 다시 배치하면 나타났다.
- 03에서 교체 선수를 선택한 뒤 요약 카드가 선발 → 교체 순서로 각각 0.5Q와 골·도움을 표시하는 것을 확인했다.
- 기존 프론트 테스트 41개, TypeScript 검사, Vite 빌드가 통과했다. 브라우저 확인은 가상 데이터로 수행했으며 실제 DB·운영 서버에는 반영하지 않았다.

## 01 참석 선택 카드 확인 (2026-10-15)

- 375 / 390 / 430px에서 4열과 간격 6px, 350px에서 3열을 확인했다. 1280px에서는 기존 자동 열 배치를 유지하며 각 크기에서 카드와 페이지의 가로 넘침이 없었다.
- 카드 전체 클릭으로 미배치 선수의 참석 선택을 해제하면 25명에서 24명으로 바뀌고, 다시 선택하면 25명이 됐다. 선택한 선수만 보기에서 해제한 선수가 제외되며 이름 검색도 동작했다.
- TypeScript 검사와 Vite 빌드가 통과했다. 이번 추가 변경은 화면 구성과 CSS만 수정했으며 단위 테스트·백엔드·MySQL 테스트를 다시 실행하지 않았다. 실제 iPhone Safari 확인은 아직 수행하지 않았다.
- 가상 데이터 임시 미리보기에만 반영했으며 운영 배포와 Git push는 수행하지 않았다.
