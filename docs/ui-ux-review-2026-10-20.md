## 판단

## 기능 명세·화면 흐름

1. 로그인 → 팀 이름 옆 **우리 팀 홈 →**으로 언제든 홈 복귀. **팀 · 접속 관리**를 팀 정보와 같은 행에 배치한다.
2. 홈 → 작성 중 기록이 있을 때 이어쓰기 표시. 없으면 최근 경기를 먼저 보여 주고 작은 초안 안내를 남긴다.
3. 선수 기록 → 기간·경기 조건 → 세 가지 요약 → 결과. 상세 집계 설명은 **집계 내역**, 스탯 기준·정렬·페이지 인원은 **보기 설정**에서 펼친다. 적용 설정은 닫힌 제목에 표시하며 검색·간단/표 전환은 항상 보인다.
4. 경기 결과 → 반복 소개 제목을 줄이고 점수·타임라인·쿼터별 스쿼드를 먼저 읽는다.
5. 팀 관리 → **팀 로고** 독립 화면. 다른 화면으로 이동하면 로고 창이 남지 않는다. 파일을 선택한 뒤 저장하지 않고 이동하면 확인하고, 업로드 중에는 이동을 막는다.

보조 설명 대비를 개선하고 수정/삭제·득실점 순서 펼치기는 최소 높이44px로 맞췄다. textarea 키보드 포커스와 화면 전환 후 주요 영역 포커스를 보완했다. 권한·집계·저장 API·DB는 변경하지 않았다.

## 검증

- 프론트 회귀 테스트 312개, TypeScript, 배포 빌드 통과.
- 가상 선수47명/경기3건으로 모바일320·390px, 데스크톱1280px 확인. 선수단·여러 명 입력·대회 빈 상태·홈·통계·경기 보고서·관리 메뉴 확인. 페이지 자체의 가로 넘침 없음.
- 같은390px 가상 표 화면 첫 행 위치 **1390.30 → 837.20 CSS px**, 약39.8% 감소. 사용 시간이나 사용성 점수의 측정이 아니다.
- 보기 설정 펼침/누적→2쿼터당/10→20명/닫힌 요약 반영 확인.
- 가상 로고 파일 선택 → 이동 경고 → 계속 작성 시 미리보기 유지 → 저장 안 하고 이동 시 독립 화면 제거 확인.
- 회원7·운영진21쪽 가이드 전체 렌더 검수. 가이드1.17을 앱 빌드와 함께 준비했다.
- 실제 iPhone/Safari·야외 가독성·스크린리더 직접 사용·운영 자료 쓰기는 미실행. 이번 로컬 Java/MySQL 재시험은 하지 않았으며 배포 전 GitHub CI 결과를 별도로 확인한다.

## 후속 우선순위

1. 실경기에서 참석 선택→배치→교체→득점→저장의 막힌 부분을 수집한다.
2. 메뉴 이동 후 조회 조건 유지와 목록 페이지 이동 포커스를 일관되게 설계한다.
3. 누적된 CSS를 공통 버튼·필터·배지 단위로 정리하고 초기 JavaScript 묶음을 나눈다. 현재 빌드의 큰 청크 경고는 오류가 아니며 별도 성능 작업으로 남긴다.
