# 경기 입력 알림과 쿼터 상세

2026-10-19 · 운영 반영 2026-10-19 20:37:41 KST

## 범위와 화면 흐름

- 02 작전판 X 또는 선수 선택 창의 해제: 해당 구간에 골·도움이 있으면 기존 보호 규칙대로 변경을 거절하고 4초 후 페이드아웃하는 알림. 같은 오류를 다시 눌러도 새로 알림. 모달에서도 알림이 가려지지 않는다.
- 03 골 추가: 처음에는 접힌 `골 추가`를 열고 득점자·도움을 선택. 기존 골 기록은 계속 보인다.
- 03 외부 경기 실점: 숫자 입력과 −/+ 버튼. 0~99, 미입력에서 +는 1, 0에서 감소 불가. 최종 스코어 합산은 기존 규칙 유지. 자체전은 상대 팀 득점에서 계산한다.
- 목록: 기존 득점 요약 → `쿼터별 기록 펼치기` → 전반/후반 또는 1~4쿼터별 득점자·도움·양수 실점. 접으면 요약으로 돌아간다. 자체전은 A/B팀을 구분한다.
- 상세는 펼칠 때 기존 팀 권한의 경기 조회 API로 읽는다. 접기·이동 시 요청 취소, 재시도 및 세션 만료 처리. 예전 합계는 골/도움 연결을 추측하지 않고 합계임을 표시한다. 미입력 실점은 무실점으로 단정하지 않는다.

## 검증 / 배포

가상 자료로 외부/자체전, 전후반/4쿼터, 연결 기록/예전 합계, 반복 알림·자동 사라짐·모달 표시·실점 경계·펼치기를 확인한다. DB/API 스키마 변경 없음. 웹만 배포하고 기존 API V32와 운영 자료는 유지한다. 운영진·회원 가이드와 안내 그림을 함께 갱신한다.

로컬 검증: 프론트 288개 통과·타입 검사·배포 빌드 성공. 가상 390×844에서 X/모달 해제 거절과 알림 자동 사라짐, 도움 선수 보호, 실점 증감·0/99 경계·최종 합계, 골 추가 접힘/열림, 목록 구간 펼치기를 확인했다. 역할별 PDF 25쪽을 렌더링해 확인했다. 실제 iPhone Safari는 미검증. DB 구조 변경이 없어 ERD는 V32 유지.

운영 검증: 웹 `43e8fd67451b6b6fc93932d562316ba8d4c9a64d` 배포 완료. API `1519c9dbe84d735943ccae7ba73188268ec6ba92`와 DB V32는 유지했다. [GitHub CI](https://github.com/ksmlucky/jochook-on/actions/runs/39244719182)에서 프론트·서버·MySQL 통합·빌드를 통과했다. 공개 HTTPS, 배포 JS/CSS/역할별 PDF의 로컬 빌드 해시 일치, 기존 감독 로그인·조회·팀 권한을 확인했다. 가상 회원 화면에서 전반/후반과 자체전 A/B팀별 실점도 확인했다. 운영 기록 쓰기·실제 iPhone·로컬 Java/MySQL 테스트는 하지 않았다. 가이드1.13의 공통 원본·공유본·앱 반영을 확인했다.

휴대폰 확인: 02 기록 있는 선수 X 알림 → 03 골 추가 펼치기와 실점 −/+ → 목록의 쿼터별 기록 펼치기. 웹 문제 시 이전 웹1519c9d로 되돌릴 수 있으며 API/DB를 변경할 필요는 없다.
