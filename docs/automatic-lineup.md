# 4쿼터 자동 편성

01에서 참석 예정자를 고르고 **참석 명단 확인 · 1~4쿼터 자동 편성**을 누르면 02 계획을 채운다. 기존 계획은 교체 확인 후 바꾼다. 계산 결과는 초안이며 **계획 저장 · 실제 기록으로** 또는 **경기 기록 저장**을 눌러야 DB에 저장된다. 실제 출석·득점·도움은 자동으로 바뀌지 않는다.

2026-10-15 로컬 확장판은 4-1-2-3 / 4-4-2 / 4-2-3-1 / 4-1-4-1 / 3-5-2 / 3-4-3을 지원한다. 운영 서버는 아직 기존 4-1-2-3이다. [포메이션 명세](player-stats-and-formations.md)를 따른다.

## 편성 기준

02에서 추가한 용병도 참석 예정자로 포함하며 같은 선호·GK·출석률 규칙을 적용한다. 용병 프로필은 다음 경기에도 같은 ID로 재선택한다. 계산 후 용병을 추가했다면 자동 편성을 다시 실행하거나 수동으로 배치해야 한다. 03의 **02 계획대로 참석·출전 기록 저장**은 운영진이 별도로 누르는 저장 동작이며, 이때 참석 예정자의 미확인 출석과 실제 배치를 함께 기록한다.

1. 참석 예정자 중 선호 1~3지망에 GK가 하나라도 있는 선수는 **GK 전용 그룹**이다. 나머지는 필드 그룹으로 나눈다. 포지션 미확인 선수는 경고하고 자동 배치에서 제외한다.
2. 선택 포메이션의 GK 1자리와 필드 10자리를 쿼터마다 채운다. 그룹 인원이 부족하면 가능한 인원만 배치하고 빈 자리를 알린다. GK 한 명이면 4쿼터 모두 맡는다.
3. 선수는 같은 쿼터에 한 자리만 배치한다. 교체는 같은 자리 두 명이 각 0.5쿼터를 뛰며, 교체 없는 선발은 1쿼터다. 자동 배치 대상은 **두 쿼터 연속 쉬지 않으며**, 같은 그룹의 총 출전량 차이는 **최대 1쿼터**다.
4. 위 조건 안에서 **1~3쿼터 교체 최소화 → 출전량 균등화 → 전체 교체 최소화** 순서로 출전표를 계산한다. 균등화는 총 출전량 제곱 합을 줄이는 방식이다. 사용자 확인에 따라 앞 세 쿼터의 교체 최소화를 0.5쿼터 단위 완전 균등보다 우선한다.
5. 그룹 내 출전량은 과거 출석률이 높은 순서대로 많거나 같게 배분한다. 비선호 배치를 피하려고 출석 우선권을 뒤집지는 않는다. 동률은 요청 시드로 추첨한 순서다.
6. 개인별 출전량과 쿼터별 교체 수를 고정한 뒤, 연속 휴식 금지와 자리 정원을 지키면서 선호 포지션 점수를 높인다. **1지망 100 / 2지망 60 / 3지망 30 / 비선호 필드 0**, 실제 배정량(1 또는 0.5Q)에 비례한다. CB는 LCB/CCB/RCB, CM은 LCM/RCM, CDM은 LCDM/RCDM, ST는 LST/RST에 같은 점수다. 로컬 확장판에서 LW↔LM, RW↔RM, CM↔CAM, LB↔LWB, LM↔LWB, RB↔RWB, RM↔RWB 인접 역할은 20/12/6점으로 정확한 3지망보다 낮고 비선호 배치로 안내한다.

예를 들어 필드 11명이면 총 40쿼터분을 나눈다. 앞 3쿼터 교체 없이, 4쿼터 한 자리에서 1:1 교체하는 경우 출전량은 6명×4Q + 2명×3.5Q + 3명×3Q다. 추가 출전량은 출석률 순이며, 같은 출석률 안에서는 추첨한다. GK의 4쿼터분은 별도로 나눈다.

## 출석률의 분모

`현재 경기일보다 앞선 경기의 (PRESENT + LATE) / (PRESENT + LATE + ABSENT)`

- 선수별로 참가 명단에 저장된 실제 출석만 집계한다. 투표는 분자·분모에 쓰지 않는다.
- UNCONFIRMED, 참가 명단에 없는 경기, 같은 날짜와 이후 경기는 제외한다. 편집 중인 경기는 날짜를 바꾸었더라도 matchId로 제외한다.
- 기록이 없으면 화면에는 **기록 없음**, 우선순위에서는 0%와 동일하게 처리한다. 반올림 전 분수로 비교한다.
- 전체 누적 기록을 사용하며 시즌·최근 N경기 필터는 후속 기능이다. 불참을 미확인으로 남겨 두면 분모에도 포함되지 않으므로 경기 후 출석 확인이 필요하다.

## 구조와 계산 한계

- `LineupSuggestionController` → `LineupSuggestionService`가 DB의 선호 포지션과 출석 집계를 읽는다. `QuarterSchedule`과 `LineupOptimizer`는 DB 없이 검증 가능한 순수 계산 코드다.
- 휴식·교체·균등 배분이 동시에 걸린 정수 제약 문제여서 [Google OR-Tools CP-SAT의 Java API](https://developers.google.com/optimization/scheduling/employee_scheduling)를 사용한다. 두 단계로 나눠 자리 변수 전체를 처음부터 탐색하는 비용을 줄였다.
- 라이브러리는 Gradle이 Maven Central에서 받는다. 별도 프로그램이나 유료 서비스는 필요 없다. 운영체제별 네이티브 라이브러리가 포함되어 JAR 크기가 커지고 첫 실행 때 임시 디렉터리에 로드된다. 계산기는 Windows x64와 GitHub Actions의 Linux x64에서, DB 연동은 Docker MySQL로 검증했다. ARM 등 다른 배포 환경은 네이티브 호환성을 별도로 확인해야 한다.
- 그룹별 각 단계에 최대 3초 및 deterministic time 1의 제한을 두고 한 작업 스레드를 사용한다. 동일 입력/시드로 재현하기 쉽게 했지만 시간 제한이 먼저 걸리면 환경에 따라 결과가 달라질 수 있다. 동시에 한 요청만 계산한다.
- 정확히 두 조(GK 2명 또는 필드 20명)는 두 조가 번갈아 2쿼터씩 출전하는 교체 없는 최적 출전표를 바로 만든다. 이 경우 서버 속도나 탐색 시간에 따라 불필요한 앞 쿼터 교체가 생기지 않는다. 그 출전량 아래에서 선호 포지션 배치를 최적화하는 다음 단계는 동일하다.
- 자리 탐색 시간이 끝나면 찾은 유효한 해를 사용하고, 없으면 앞 단계의 출전표를 유효한 자리 배치로 바꿔 반환한다. 이 경우 선호 배치와 최적 여부에 대한 경고를 보여준다. 출전표 자체를 못 찾으면 실패 응답이며 화면의 기존 계획을 유지한다.
- 응답의 `optimal`은 **두 단계가 각각 최적 종료했는지**다. 앞 단계에서 고정한 개인 출전량·쿼터별 교체 수 아래의 최적이므로 전체 문제의 전역 최적을 주장하지 않는다.
- GK 5명 이상 또는 필드 41명 이상은 두 인접 쿼터에 모두 한 번씩 뛰게 할 수 없어 거부한다. GK 3~4명 또는 필드 21명 이상이면 연속 휴식을 피하려고 앞 세 쿼터에도 교체가 필요할 수 있다.
- 특정 쿼터만 참석, 고정 배치, 연령 정원, 쿼터별 포메이션 변경, 개인 실력은 이번 계산에 포함하지 않는다. 네 쿼터 모두 참여 가능하다고 가정한다.
- 자동 편성 결과는 운영진이 드래그로 바꿀 수 있다. 수동 수정은 자동 조건을 다시 강제하지 않으며 표에서 현재 출전량·휴식·비선호 배치를 확인한다. 추첨 시드와 출석률 스냅샷은 영구 저장하지 않고 최종 계획만 기존 V10 테이블에 저장한다. 기존 자동 편성 도입에는 새 마이그레이션이 없었으며 이번 포메이션 확장에는 V21과 V22가 필요하다. V21에서 4백 네 종류, V22에서 3백 두 종류와 윙백을 추가한다.
