# 2026.10.15 기능확장판 배포 기록

상태: 배포 전 검증 중. 실제 운영 완료 여부와 커밋은 아래 검증이 끝난 뒤 확정한다.

## 이번 범위

- 선수 시즌 기록: 득점·도움·출전 경기·출전 쿼터·실제 참석을 연도별 조회. 기본은 완료된 외부 경기와 회원이며 자체전·용병·이전 상태 미지정 경기 포함은 필터로 선택한다.
- 포메이션 6종: 4-1-2-3, 4-4-2, 4-2-3-1, 4-1-4-1, 3-5-2, 3-4-3과 새 선호 포지션.
- 02·03 한눈에 보기에서 자리 선택 후 배치·교체와 골·도움 편집. 모바일 3-5-2 반응형 배치.
- 같은 탭·계정·팀 범위에서 최대 24시간 초안 보관, 저장 응답을 확인하지 못했을 때 중복 생성 방지와 결과 확인.
- 안내문구 정리와 접을 수 있는 부가 설명, 앱 안의 역할별 사용자 가이드·PDF 다운로드.
- 백업 점검·격리 복원 도구와 가이드 유지관리 문서를 Git에 포함한다. 자동 백업 일정은 별도 미해결 과제로 남긴다.

## 배포·복구 원칙

기존 Northflank API·웹·MySQL과 무료 사양을 유지한다. 실제 데이터·계정·팀 코드는 시험 수정하지 않는다. Oracle 이전, 유료 자원, 추가 권한, 새 외부 포트를 만들지 않는다.

1. 운영 DB를 비공개 TLS로 읽어 DPAPI 암호화 백업하고 별도 로컬 MySQL에 복원한다.
2. 기존 15개 테이블의 전체 행 지문과 V20 이력을 대조한 뒤 임시 복원 서버·데이터를 정리한다.
3. 배포할 커밋의 GitHub CI에서 Java/API·Docker MySQL 통합·프론트·백업 도구 테스트와 빌드가 모두 통과해야 한다.
4. 같은 커밋으로 API를 먼저 배포해 V21~V23 및 readiness를 확인한 뒤 웹을 배포한다.
5. 기존 컬럼의 행 지문, 새 스키마, 공개 HTTPS·세션·권한·조회·가이드 자산을 확인한다.

마이그레이션은 기존 포메이션 F4123을 유지하고 허용값을 확장하며 저장 영수증 테이블을 추가한다. 새 포메이션의 데이터가 생기면 이전 앱이 그 값을 해석하지 못할 수 있으므로 단순 앱 롤백을 자동 수행하지 않는다. 장애 시 입력 중단·현재 DB 추가 백업 후 복구 범위를 판단한다. 운영 DB에 예전 덤프를 바로 덮어쓰지 않는다.

배포 직전 백업은 Git 제외 `backups/northflank/20261015-before-feature-expansion/`에 있다. DPAPI는 이 Windows 사용자에 종속되므로 PC 분실 대비 독립 백업은 아니다.

## 휴대폰 확인 항목

1. 새로고침하고 필요하면 기존 계정으로 다시 로그인한다.
2. 선수 기록의 연도·필터, 02·03의 포메이션·한눈에 보기 편집을 확인한다.
3. 운영진/회원 접속에서 사용 가이드가 역할에 맞게 열리는지 확인한다.
4. 실제 경기 입력은 필요한 업무 자료로만 진행한다. 확인만을 위해 기존 기록을 바꾸지 않는다.

자동 검증·실제 배포·실기기 확인의 결과는 각각 구분해 기록한다. 실제 iPhone Safari 확인은 사용자 확인 단계다.
