# 골·도움 연결 기록과 모바일 작전판

기준: 2026-10-19 **로컬 개발·미배포**. 운영 웹은 `a229bbb`, API는 `d8b2763`, 운영 DB는 V30, 운영 가이드는 1.8을 유지한다. 이 문서는 새 기능의 명세와 검증 기준이며 운영 반영 확인서가 아니다.

## 목표와 범위

02 스쿼드·기록에서 전반/후반 또는 쿼터별로 **골 한 건의 득점 선수와 도움 선수**를 연결한다. 연결한 기록을 기준으로 선수별 골·도움·직접 프리킥·페널티킥 합계를 계산한다. 기존 기간·대회·리그 필터와 기록 완료 집계 정책은 유지한다.

운영진이 모바일 작전판의 자리를 누르면 해당 자리의 선수 선택과 교체를 바로 편집한다. 명단과 작전판 사이를 오갈 필요를 줄이고, 선수 선택 안내 때문에 화면이 밀리는 현상을 제거한다. 자리 교환은 별도 모드로 구분한다.

## 골 기록 정책

| 항목 | 정책 |
| --- | --- |
| 구간 | 경기 형식에 따른 1~4쿼터 또는 전반·후반 |
| 득점 선수 | 필수. 해당 구간에 실제 배치된 선수 |
| 도움 선수 | 선택. 같은 구간·같은 팀에 배치된 다른 선수 |
| 득점 종류 | 일반 득점, 직접 프리킥, 페널티킥 |
| 직접 프리킥·PK | 총 득점의 일부. 도움 선수는 기록하지 않음 |
| 도움 미입력 | 도움 없음 또는 아직 확인하지 못한 상태. 임의 선수 배정 없음 |
| 자체전 | A/B팀별 출전 배치를 기준으로 같은 팀 안에서만 연결 |
| 시간 | 득점 분·초는 이번 범위에서 입력하지 않음 |
| 시즌 반영 | 저장한 연결 기록에서 출전별 합계를 계산. 기본 시즌 집계는 기록 완료된 경기 기준 |
| 팀 스코어 | 기존 직접 입력 유지. 선수 득점 합계 차이는 기존 안내 유지 |

승부차기·상대 선수의 자책골 이벤트·수정된 과거 기록의 득점자 추정은 이번 범위가 아니다. 0.5쿼터 교체 규칙과 기존 포메이션 정책도 바꾸지 않는다.

## 기존 자료와 집계

- `match_quarters.goal_events_linked` 기본값은 `FALSE`다. 과거 구간은 선수별 합계를 그대로 보존한다.
- API의 `goalEvents: null`은 기존 합계 방식, `[]`은 연결 방식의 명시적인 0골이다. 두 상태를 구분한다.
- 기존 골·도움이 있는 구간은 연결 내역을 입력하고 **선수별 총 골·도움·FK·PK 합계가 기존 값과 맞을 때** 화면에서 전환한다. 과거 골·도움을 임의로 연결하지 않는다.
- 연결 방식에서는 골 목록이 원본이다. `match_appearances`의 골·도움·FK·PK 값은 서버에서 계산하므로 직접 수정값과 이중 합산하지 않는다.
- 이미 연결된 구간을 이전 클라이언트가 목록 없이 저장할 때는 기존 목록을 보존한다. 목록과 충돌하는 수동 합계는 거부한다.
- 서버는 구간당 최대 1,000건, 선수별 통계 최대 99 및 기존 경기 유효성을 검증한다. 구간·동일 팀 출전 확인은 서비스 검증이며 복합 FK가 아니다.

## 스토리보드

1. **01 참석:** 기존대로 참석 선수와 자체전 A/B팀을 정한다.
2. **02 배치:** 작전판 자리 → 등록 가능한 선수 선택 → 선발/교체 적용. 자리 교환은 별도 모드에서 두 자리를 선택한다.
3. **02 골 기록:** 현재 구간 선택 → 득점 기록 추가 → 득점자 → 선택적 도움 선수 → 득점 종류. 예: 가상 선수 A 득점, 가상 선수 B 도움.
4. **02 확인:** 골 내역과 선수별 합계 확인. 기존 합계 방식인 구간은 값을 보존하거나 일치하는 연결 내역으로 전환한다.
5. **고정 저장:** 오른쪽 아래 저장·다음 단계 버튼으로 저장한다. 저장 안내는 약 300ms 동안 부드럽게 나타나고 사라진다. 동작 줄이기 설정에서는 애니메이션을 줄인다.
6. **03 결과:** 스코어·코멘트 확인 후 경기 완료. 선수 기록에서 동일한 득점·도움 합계를 조회한다.

선수 선택창을 열고 닫거나 선수를 바꾸는 것만으로 작전판 위치가 튀지 않아야 한다. 단계 변경·검증 오류처럼 이동 이유가 있는 경우의 포커스 이동은 유지한다. 고정 버튼은 모바일 안전 영역과 본문 마지막 줄을 가리지 않아야 한다.

## 로그인 유지 변경

개인 계정은 **마지막 서버 요청 후 7일 미사용 시 만료**하도록 변경한다. 회원 팀 코드 접속은 기존 24시간 미사용·로그인 후 최대 7일 정책을 유지한다. 로그아웃·계정 비활성화·권한 변경·비밀번호 변경 등 세션 무효화 규칙은 유지한다.

현재 서버 메모리의 HttpSession을 사용하므로 서버가 재시작하면 다시 로그인해야 한다. 세션 쿠키의 보관은 브라우저에 영향을 받으며, 앱을 닫아도 무조건 7일간 유지되는 영구 로그인 기능을 뜻하지 않는다.

## 인수 기준과 검증 범위

- 일반 골 1건 + 도움 1명을 저장하면 득점자 1골·도움 선수 1도움으로 반영한다.
- 직접 FK·PK는 총 골에 포함하고 도움은 거부한다. 자기 도움·다른 팀·다른 구간·출전하지 않은 선수도 거부한다.
- 골 추가·수정·삭제 후 합계를 재계산하고, 기존 합계 구간 및 누락된 연결 목록의 호환을 검증한다.
- 선수 이동·교체·참석 변경으로 연결이 유효하지 않게 되면 조용히 다른 선수에게 기록을 옮기지 않는다.
- 저장 실패·세션 만료·재로그인·초안 복원에서 골 목록을 보존한다.
- 가상 데이터로 작은 화면, 자리 선택, 명시적 교환, 고정 버튼, 알림 입장·퇴장을 확인한다.
- 단위/프론트 검증과 MySQL 통합 검증을 구분한다. 실제 운영 DB 쓰기·배포·실제 iPhone 확인은 이 문서 작성으로 수행된 것으로 간주하지 않는다.

구현·통합 검증 결과는 총괄 완료 보고와 검증 문서에서 확정한다. ERD 생성 검증은 SQL의 테이블·FK 대조와 도식 렌더 확인이며 실제 MySQL 마이그레이션 검증을 대신하지 않는다.

### 2026-10-19 로컬 검증 결과

- 백엔드 단위/API 485개 통과. 테스트 XML에서도 실패·오류 0 확인.
- 격리한 native MySQL 8.4에서 10개 통과: 연결 기록 저장/조회/수정/삭제·이력·시즌 합계, V30→V31 기존 자료 보존과 제약, 기존 마이그레이션 회귀. 실제 팀 DB는 사용하지 않았고 임시 서버는 종료했다. Docker 엔진이 없어 Testcontainers 실행은 하지 못했다.
- 신규 프론트 로직 6개 통과: 자동 합계, 잘못된 도움, 과거 합계 전환, 배치 보호, 초안/재시도, 연결 변경 이력. 최신 소스 TypeScript 검사 통과.
- 전체 프론트 회귀 테스트 276개와 최종 TypeScript·Vite 빌드가 통과했다. 가상 데이터의 390px·320px 브라우저에서 작전판 자리 선택, 교체 선수 지정, 닫은 뒤 스크롤 복귀, 하단 고정 저장 버튼 및 가로 넘침 없음을 확인했다. 기존 득점의 도움 연결 전환 화면도 확인했다. 실제 iPhone 동작은 아직 확인하지 않았다.
- ERD PNG 6장 렌더 및 신규 골 연결 그림 육안 확인. `git diff --check` 통과.
- 운영 DB 마이그레이션·배포·실제 iPhone 확인·이번 변경 GitHub 업로드는 수행하지 않았다. 운영 가이드 1.8은 그대로 유지한다.

## 가이드와 운영 반영

운영진 가이드에는 자리 선택·고정 저장·골과 도움 연결·기존 구간 전환·7일 계정 세션을 반영해야 한다. 회원 가이드는 골·도움 합계의 연결 의미와 회원 코드 세션 정책이 그대로인지 점검한다. 사용자 배포 요청 후 `docs/guides/content.json`, HTML, PDF를 가이드 1.9 배포 준비본으로 갱신했다. 회원 7쪽·운영진 19쪽 총 26쪽을 렌더링해 확인했으며 `maintenance.json`과 공통 원고의 상태는 `pending_deployment`, 대상 커밋은 미확정이다. 실제 운영 가이드 1.8·DB V30 상태는 아직 유지한다.
