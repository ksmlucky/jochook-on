# 팀 코드와 자동 생성 팀 비밀번호

기준일: 2026-10-14. **회원 접속에 팀 코드와 팀 비밀번호를 함께 받고, 코드 발급 때 비밀번호도 자동 생성한다는 사용자 요청을 반영한다.** 비밀번호 길이는 총괄이 권고한 숫자 6자리를 이번 구현 기준으로 사용한다. V17 구현·로컬 적용과 자동 검증을 완료했다. 실행한 검증과 미검증 UI 항목은 문서 마지막과 검증 기록에 구분한다.

## 1. 목적과 범위

회원은 개인 계정 없이 팀 코드와 팀 비밀번호 두 값을 입력해 해당 팀 기록을 조회한다. 운영진은 기존 개인 계정으로 수정하고 코드·팀 비밀번호를 관리한다. 팀 비밀번호는 개인 계정 비밀번호와 별개다. 두 값은 같은 팀이 공유하는 조회용 비밀이며 개인 신원 확인이나 2단계 인증(2FA)이 아니다.

이번 변경은 코드 접속·발급 응답·팀 코드 저장 구조를 확장한다. 선수·경기·팀 소속 데이터와 운영진 개인 계정 비밀번호는 변경하지 않는다. 기존 팀 기능은 [요구사항](team-access-requirements.md), 통신 형식은 [API 계약](team-access-api.md)을 따른다.

## 2. 운영 정책과 인수 기준

| ID | 정책 | 인수 기준 |
| --- | --- | --- |
| TCP-R01 | 기존 무작위 12자 팀 코드와 독립적으로 숫자 6자리 팀 비밀번호를 생성한다. | 비밀번호는 문자열로 다뤄 맨 앞의 0도 유지한다. 코드·이름·등번호에서 비밀번호를 유도하지 않는다. 숫자 6자리만으로 접속할 수 없다. |
| TCP-R02 | 회원은 한 화면에서 두 값을 입력하고 한 번에 확인한다. | `{code, password}`로 요청한다. 코드만 먼저 확인해 팀 존재·이름을 알려 주는 API나 중간 화면을 만들지 않는다. |
| TCP-R03 | 해당 팀 운영진만 두 값을 발급한다. | 발급·재발급 때 두 값을 함께 새로 만들고 같은 version·90일 만료일로 관리한다. 일부만 갱신되어 유효 조합이 엇갈리지 않는다. |
| TCP-R04 | 원문은 성공 응답에서 한 번만 공개한다. | 발급 결과에 두 값을 구분해 표시하고 개별 복사 버튼을 제공한다. 닫은 뒤 재조회·상태·이력에는 코드와 비밀번호 원문·해시가 없다. |
| TCP-R05 | 저장·노출 범위를 제한한다. | 코드는 기존 SHA-256, 팀 비밀번호는 BCrypt 해시만 DB에 저장한다. 두 원문을 URL·로그·브라우저 localStorage/sessionStorage·오프라인 캐시에 저장하지 않는다. 사용자가 누른 복사·직접 전달만 지원한다. |
| TCP-R06 | 재발급·폐기는 기존 조합과 조회 세션을 무효화한다. | 이후 시작한 기존 코드 세션의 API 요청을 거부한다. 개인 운영진 로그인은 유지한다. 분실·발급 응답 유실 시 상태를 확인하고 두 값을 재발급한다. |
| TCP-R07 | 접속 실패 원인을 공개적으로 구분하지 않는다. | 틀린 코드·틀린 비밀번호·없는 코드·만료·폐기는 같은 오류 상태와 문구를 반환한다. IP/브라우저별 10분 내 실패 10회 뒤 10분 대기 정책을 유지한다. |
| TCP-R08 | 비밀번호 없는 구 코드로는 접속할 수 없다. | V17 이후 비밀번호 해시가 없는 코드는 새 접속과 기존 조회 세션 모두 거부한다. 운영진은 두 값을 새로 발급해 공유한다. 운영진 개인 계정·기존 선수·경기는 보존한다. |
| TCP-R09 | 입력·통신 오류를 안전하게 처리한다. | 비밀번호 입력은 마스킹하고 숫자 키패드·붙여넣기를 지원한다. 실패한 새 조합 때문에 유효한 기존 조회 접속을 성공처럼 다른 팀으로 바꾸지 않는다. 처리 중 중복 요청을 막는다. |

기존 조회 세션의 유휴 24시간/최대 7일, 운영진 계정의 유휴 30분은 유지한다. 두 값의 재발급·폐기·만료가 먼저 발생하면 그 조건이 우선한다. 이미 본 화면이나 캡처를 회수하는 기능은 아니다.

숫자 6자리는 12자 무작위 코드와 함께 쓰는 이 서비스의 보조 접속 정책이다. 이를 독립 로그인 비밀번호나 강한 개인 계정 비밀번호 기준으로 설명하지 않는다. [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)의 일반 오류 응답과 로그인 시도 제한 원칙을 참고하며, OWASP가 숫자 6자리를 안전한 비밀번호로 권고했다는 의미는 아니다.

## 3. 스토리보드

```text
TCP-S01 회원 접속 — 한 화면
  조축ON / 우리 팀 들어가기
  팀 코드      [운영진에게 받은 코드]
  팀 비밀번호  [마스킹된 입력]
  [우리 팀 들어가기]  [운영진 로그인]
      ├ 두 값 유효 → 현재 팀의 선수단·경기 조회
      └ 실패 → 코드와 팀 비밀번호를 함께 확인하라는 안내

TCP-S02 운영진 발급 결과 — 원문 1회
  팀 코드      [발급 원문] [코드 복사]
  팀 비밀번호  [발급 원문] [비밀번호 복사]
  공통 만료일 / 두 값을 팀원에게 전달하라는 안내
  [확인했어요 · 닫기]
      ↓ 닫기
  원문 대신 상태·만료일·발급 이력 / [다시 발급]

TCP-S03 재발급·폐기 확인
  이전 코드와 비밀번호를 사용할 수 없고
  기존 회원 조회 접속도 종료된다는 안내
  [취소] [재발급 또는 폐기]
```

| 화면 | 동작·상태 | 연결 요건 |
| --- | --- | --- |
| TCP-S01 | 빈 입력은 해당 필드에 안내한다. 서버는 두 값을 함께 검증하며 어느 값이 맞았는지 알려 주지 않는다. 대기 제한·통신 실패는 다음 행동을 안내한다. | TCP-R01~02, TCP-R07~09 |
| TCP-S02 | 원문은 화면 메모리에만 보관한다. 두 복사 버튼은 각각 어떤 값을 복사했는지 알린다. 자동 메시지 전송은 하지 않는다. | TCP-R03~05 |
| TCP-S03 | 재발급 성공이면 두 값을 다시 공유한다. 취소하면 기존 조합을 유지하고, 동시 변경 충돌이면 최신 상태 확인을 안내한다. | TCP-R06, TCP-R08 |

## 4. 변경 계약과 검증 상태

- `POST /api/v1/auth/team-code`: `{code: string, password: string}`. 코드 단독 요청으로 접속하지 않는다.
- `POST /api/v1/team/code`: 기존 version 요청은 유지하고 `CodeIssued` 성공 응답에 `password: string`을 추가한다. 상태 조회·이력·폐기 응답에는 원문을 포함하지 않는다.
- `V17__add_team_code_password.sql`로 `team_codes.password_hash VARCHAR(100) NULL`을 추가한다. 기존 코드 해시가 있는 행은 해시 제거·폐기 시각 설정·version 증가로 무효화한다. 이미 적용된 V14~V16은 수정하지 않는다. 세부 이전 기준과 적용 상태는 [DB 문서](database.md)를 따른다.

- [x] 발급·재발급 응답의 두 값, 숫자 길이와 앞 0 보존, BCrypt 저장 확인
- [x] 맞는 조합만 성공하고 틀림·없음·만료·폐기 오류가 같으며 실패 제한이 유지되는지 검증
- [x] 재발급·폐기·V17 전환 후 구 코드 및 기존 조회 세션 거부, 운영진 로그인 유지 확인
- [ ] 상태·이력·URL·로그·브라우저 저장소·캐시에 원문이 없는지 확인
- [ ] 두 필드 접속, 개별 복사·닫기·재발급 안내를 가상 팀으로 브라우저 검증
- [x] 실제 적용과 실행한 자동 테스트 결과를 검증 기록에 반영

2026-10-14 V17 로컬 적용 완료. Java 단위/API 168개·MySQL 통합 51개·프론트 29개 및 격리 HTTP 흐름 29개를 통과했다. 브라우저의 틀린 조합/정상 회원 접속은 확인했다. 상태·이력 비밀 비노출은 API 테스트로 확인했지만 모든 브라우저 저장소·캐시의 종합 점검과 발급 결과 복사 버튼은 이번에 재검증하지 않아 해당 체크는 남긴다. 상세 결과는 [검증 기록](verification.md)을 따른다.

예시에는 실제 코드나 숫자 비밀번호 원문을 쓰지 않는다. 이 문서는 구현 기준이며 위 체크를 실행 결과 없이 완료 처리하지 않는다.
