## 이번 범위

전체 리뷰에서 발견한 “접속 후 무엇을 할지 찾기 어렵다”는 문제를 먼저 줄인다. 현재 비밀번호를 아는 개인 계정에는 변경 경로를 제공한다. 사용자가 승인한 정책에 따라 비밀번호를 잊은 운영진에게 서비스 관리자가 본인 확인 후 30분·일회용 복구 링크를 발급한다.

자동 백업은 설정 완료로 보고하지 않는다. 기존 무료 계정의 daily 예약 거절과 공개 문서의 일반 기능 설명을 구분한다. 이번에는 읽기 전용 상태 확인과 상태 점검 스크립트의 결함 수정을 수행했다.

## 요구사항과 화면 흐름

### 우리 팀 홈

`팀 접속/로그인 → 우리 팀 홈 → 최근 경기 / 선수 기록 / 선수단`

- 회원: 최근 경기 최대 3건을 조회하고 원본 경기로 이동한다. 입력 버튼은 제공하지 않는다.
- 감독·코치: 새 경기 기록, 저장된 미완료 경기 최대 2건 이어서 작성도 제공한다.
- API 첫 10건 안에서 선택한다. 전체 과거 미완료 경기를 찾은 것처럼 표시하지 않는다. 이전의 상태 미지정 기록은 임의로 미완료 처리하지 않는다.
- 홈에서 경기 열기 시 탭에 보관 중인 초안이 있으면 복원·폐기를 먼저 안내한다. 초안을 새 기록으로 덮어쓰지 않는다.
- 조회 실패에는 다시 시도를 제공한다. 팀 변경/이동 후 늦게 도착한 조회 응답은 적용하지 않는다.
- 로고 또는 `팀 · 접속 관리 → 우리 팀 홈`으로 돌아온다. 기존 `#players`, `#matches` 등 직접 링크는 유지한다.
- 홈 주소는 `#home`으로 정규화하여 홈→경기→브라우저 뒤로가기를 지원한다.

### 본인 비밀번호 변경

`팀 · 접속 관리 → 내 비밀번호 변경 → 현재/새/확인 입력 → 변경 → 새 비밀번호로 로그인`

- 개인 계정 전용이며 팀 코드 접속자는 사용할 수 없다. 팀을 선택하지 않은 개인 계정도 본인 비밀번호를 변경할 수 있다.
- POST `/api/v1/auth/password/change`, CSRF 검사. 현재 비밀번호 일치, 새 비밀번호 12 Unicode 문자 이상·UTF-8 72바이트 이하·현재와 다름을 검증한다.
- 중복 클릭과 실패 반복 시도를 제한한다. 네트워크 응답을 받지 못하면 자동 재시도하지 않고 이미 변경됐을 가능성을 안내한다.
- 입력한 비밀번호는 브라우저 저장소·문서·로그에 남기지 않는다. 전송이 끝나면 폼 값을 지운다.
- 변경 성공 시 현재 세션은 종료하고, 다른 기존 세션은 다음 요청에서 거부한다. 팀 공유 코드/팀 비밀번호는 변경하지 않는다.
- 현재 탭에서 본인 비밀번호 변경을 완료하면 해당 개인 계정의 보관 초안도 지운다. 다른 기기의 초안은 기존 재로그인/보관 정책을 따른다. 저장된 경기 데이터에는 영향이 없다.

### 운영진 비밀번호 분실 복구

`서비스 관리자 → 팀 · 접속 관리 → 운영진 계정 복구 → 아이디 검색 → 대상 선택 → 기존 연락처로 본인 확인 → 확인 후 발급 → 링크 전달`

`운영진 → 복구 링크 열기 → 계정·사용 기한 확인 → 새 비밀번호와 확인 입력 → 새 비밀번호 저장 → 재로그인`

- 활성 팀의 활성 감독·코치 계정만 검색·발급한다. 서비스 관리자 계정은 이 복구 경로에서 제외하며 별도 소유자 복구 절차는 후속 과제다.
- 이메일 자동 전송은 없다. 서비스 관리자가 본인 확인한 대상자에게 직접 전달한다. 30분은 이번에 합의한 서비스 정책이다.
- 32바이트 난수 토큰을 발급 시 한 번만 응답하고 DB에는 SHA-256 해시만 저장한다. 링크 재발급은 이전 미사용 링크를 폐기한다.
- 링크 열기는 소비하지 않는다. 비밀번호 설정 성공 시 사용 처리하고, 같은 계정의 나머지 링크와 기존 로그인을 무효화한다. 계정 비활성·운영진 권한 상실·기존 비밀번호 변경 후에는 링크가 거부된다.
- 만료·사용·폐기·잘못된 링크는 동일한 안내로 처리한다. CSRF와 실패 시도 제한을 적용하고, 완료 요청을 중복 전송해도 한 번만 성공한다.
- 브라우저는 `#reset=`의 토큰을 읽은 직후 주소를 `#access`로 바꾼다. 토큰은 컴포넌트 메모리에서만 사용한다. 새로고침으로 사라지면 원래 받은 링크를 다시 연다.
- 링크 발급 API는 `GET /api/v1/service/account-recovery/accounts?query=`, `POST /api/v1/service/account-recovery/{accountId}`이다. 공개 확인·완료 API는 `POST /api/v1/auth/password-reset/inspect`, `/complete`이다.
- 완료 후 자동 로그인하지 않는다. 대상 계정의 기존 세션과 현재 브라우저 세션을 종료한다. 현재 탭에서 로그인했던 개인 계정의 보관 초안도 지우므로 화면에서 미리 안내한다.
- 설계 참고: [OWASP 비밀번호 복구 지침](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)의 난수·일회용·만료 토큰, 기존 세션 무효화, 재로그인 원칙. 본인 확인은 기존에 확인된 연락 경로로 수행한다.

## DB와 배포 주의점

V29는 `accounts.credential_version BIGINT NOT NULL DEFAULT 0`을 추가한다. 비밀번호 변경 시 행 잠금 안에서 해시 교체와 버전 증가를 함께 수행한다. 로그인 시 확인한 버전과 각 요청의 현재 버전을 대조하므로, 비밀번호 변경 중 발생한 로그인·팀 선택 요청으로 예전 세션을 되살릴 수 없게 한다.

V30은 `account_password_resets`에 대상·발급자 FK, 토큰 해시 UK, 발급/만료/사용/폐기 시각과 발급 당시 인증 버전을 저장한다. 계정→복구 토큰 순으로 잠그고 비밀번호·인증 버전·토큰 사용을 같은 트랜잭션에서 변경한다.

발급·완료는 READ_COMMITTED로 동작하여 권한 확인 시점에 이미 커밋된 코치 해제·팀 비활성화를 반영한다. 팀 권한 변경 전체를 추가 잠금으로 직렬화하는 정책은 아니다.

다음 실제 배포 시 기존 개인 로그인은 재로그인이 필요하다. 회원 코드 세션은 이 계정 버전 변경 대상이 아니다. 실제 운영 DB에는 이번 작업에서 V29/V30을 적용하지 않는다.

## 가이드와 구성도 점검

- 운영진 가이드 예정 변경: 새 홈/이어서 작성/비밀번호 변경/관리자 본인 확인·복구 링크/재로그인 순서. 서비스 관리자 발급 절차는 별도 관리자 안내로 구분한다.
- 회원 가이드 예정 변경: 새 홈과 최근 경기·기록 바로가기. 회원 코드 접속 권한은 그대로다.
- 운영용 `docs/guides/content.json`·HTML·PDF·앱 가이드는 배포 전 기능을 안내하지 않도록 1.2를 유지한다. 배포할 때 함께 반영하고 역할별 화면과 PDF 전 페이지를 확인한다.
- V30 개발 ERD 원본·JSON·Mermaid·SVG·PNG·HTML을 함께 갱신한다. 업무·계정 변경 흐름은 이 문서의 새 그림에 반영한다. 서버/네트워크 구성은 변경하지 않았다.
