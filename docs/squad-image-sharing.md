# 스쿼드 이미지 공유

2026-10-19 · 로컬 구현 / 미배포

## 목적과 범위

운영진이 경기 전에 작성한 쿼터별 스쿼드를 PNG 한 장으로 저장해 단톡방에 전달한다. 02 스쿼드 배치의 `스쿼드 한눈에 보기` 옆에 `스쿼드 이미지`를 둔다. 첫 버전은 현재 선택한 구간·팀 한 장이며 공유 창에서 다른 구간·팀을 선택할 수 있다. 여러 장 일괄 공유는 후속 검토다.

## 화면 흐름과 규칙

1. 02에서 `스쿼드 이미지`를 누르면 현재 쿼터·팀으로 미리보기를 연다.
2. 전후반 경기는 전반/후반, 4쿼터 경기는 1~4쿼터를 고른다. 자체전이면 A·B팀도 고른다. 이 선택은 경기 편집의 구간·팀 선택을 바꾸지 않는다.
3. 이미지에는 팀명, 날짜·시작 시간, 상대 팀/자체전, 구간·A/B팀, 포메이션, 포지션별 선발과 교체의 이름·등번호를 넣는다. 미배치·번호 없음·선수 미확인을 명시한다. 생년·계정·팀 코드·코멘트·미배치 명단은 포함하지 않는다.
4. 현재 초안을 사용한다. 저장 전 수정 또는 새 경기는 `저장 전 · 현재 입력한 스쿼드` 표시를 넣는다. 이미지 생성·공유·다운로드는 경기 저장이 아니며 DB를 쓰지 않는다.
5. 파일 공유가 지원되면 `이미지 공유`로 운영체제 공유 창을 연다. 카카오톡 등 목적지와 수신자는 사용자가 선택한다. 앱이 자동 전송하지 않는다.
6. `PNG 다운로드`는 항상 제공한다. 공유 미지원/실패 시 이 경로를 안내하며, 취소는 실패/전송 완료로 표시하지 않는다. 구간 변경·닫기 때 미리보기 Blob URL을 해제한다.

공유 이미지 크기는 1080×1480. 브라우저 내부에서 SVG를 PNG로 변환하므로 새 서비스·라이브러리·외부 이미지 전송이 없다. 공유 버튼을 누르기 전에 PNG 파일을 준비해 모바일의 사용자 클릭 권한을 유지한다. 같은 기존 팀 조회 결과만 사용하고 운영진 화면에만 진입 버튼을 둔다. API·권한 모델·DB 변경 없음.

## 포메이션과 시각 자료

기존 6개 포메이션을 지원하며, 3-5-2는 CAM → 윙백 → CM 순으로 높이를 나눈다. 교체가 있으면 선발 카드 아래에 작은 줄로 표시한다. 공격 빨강·미드 초록·수비 파랑·GK 노랑 계열을 유지한다.

[화면 흐름·6개 포메이션 예시](diagrams/squad-sharing/index.html) · [생성 원본](../scripts/Generate-SquadShare.mjs). 실제 앱과 같은 이미지 생성 모듈로 만든 가상 예시이며 이후 기능 변경 시 함께 갱신한다. 기존 시스템 구성도와 ERD는 구조 변경이 없어 유지한다.

## 가이드 반영 계획

- 운영진: 배포 시 `스쿼드 배치와 교체` 안내에 이미지 버튼 → 구간/팀 → 미리보기 → 공유/다운로드 절차와 저장 전 표시를 추가한다. 앱 원고·HTML·PDF를 함께 갱신·렌더 확인한다.
- 회원: 첫 버전에는 직접 생성 버튼이 없고 공유받은 이미지를 확인하는 방식이다. 기존 회원 가이드 절차는 변경 없음.
- 미배포 단계에는 운영 가이드1.14를 유지하고 이 개발 문서와 maintenance.json에 반영 계획을 기록한다.

## 검증

- 293개 프론트 테스트·타입 검사·Vite 빌드 통과. 팀/쿼터 분리, 교체, 전후반, 빈 자리·용병·등번호 없음, 문자열 이스케이프, 개인정보 제외, 원본 불변, 6개 포메이션 카드 비중첩, 파일 공유 미지원/예외를 검증했다.
- 로컬 가상 데이터로 1080×1480 PNG 생성·브라우저 다운로드와 파일 렌더를 확인했다. 6개 포메이션 SVG도 렌더해 선발·교체 카드가 겹치지 않는지 확인했다.
- 390px 화면에서 자체전 A팀 1쿼터 이미지, B팀 4쿼터 전환을 확인했다. 전후반 경기에서는 전반·후반만 선택할 수 있고 팀 선택은 표시되지 않는다.
- 320px 화면에서 미리보기 대화상자의 가로 넘침이 없음을 확인했다. 새 경기의 저장 전 안내와 공유 미지원 환경의 PNG 다운로드 대체 경로를 확인했다.
- 테스트 페이지의 가상 공유 API로 PNG 파일 전달과 공유 취소 안내를 확인했다. 운영체제 공유 시트나 실제 메시지 전송을 검증한 결과는 아니다.
- 실제 iPhone/Safari 공유 시트·카카오톡 전송은 사용자 기기 확인이 필요하다. 외부 메시지 전송과 운영 데이터 쓰기는 하지 않는다. 서버/MySQL 테스트는 API·DB 변경이 없어 로컬에서 실행하지 않는다.
