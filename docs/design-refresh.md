# 조축ON 화면 디자인 개선

기준일: 2026-10-14. 사용자가 요청한 **밝고 간결하고 친근하며, 부드럽지만 명확한 느낌**을 반영했다. 화면 구현·프론트 테스트·빌드와 가상 데이터를 사용한 로컬 브라우저 검증을 완료했다. 실제 API 저장·휴대전화 설치 검증과 사용자 디자인 확인은 별도다.

## 1. 확정 방향과 구현 범위

| 구분 | 기준 | 상태 |
| --- | --- | --- |
| 분위기 | 과하게 둥글거나 장식적이지 않게, 차갑고 딱딱하지 않게 | 사용자 선호 확정 |
| 서비스와 팀 | 조축ON은 서비스, 현재 팀은 별도 영역에 표시. 팀명은 현재 접속한 팀 정보 사용 | 기존 정책 유지 |
| 탐색 | 선수단·경기 기록 중 선택한 화면 하나를 본문에 표시, 활성 메뉴에 `aria-current` 적용 | 구현·예시 화면 검증 완료 |
| 접속 | 팀 코드 입력을 먼저 찾을 수 있도록 간결하게 정리하고 운영진 로그인 경로 유지 | 구현 완료 |
| 설치 안내 | 화면 하단으로 이동. 연결 끊김 경고는 상단 고정 안내 유지 | 구현 완료 |
| 색·간격·형태 | 아래 시각 기준을 화면·PWA 아이콘·오프라인 안내에 적용 | 구현 완료, 사용자 확인 대기 |
| 작은 화면의 정보량 | 선수단 정렬·표시 설정과 자동 편성 기준을 필요할 때 펼쳐 보기 | 구현 완료, 마지막 모바일 분기 확인 중 |

기존 팀명과 실제 데이터, 회원 조회·운영진 수정 권한, API·DB·자동 편성·저장 정책은 변경하지 않는다. 여러 팀을 수용하는 서비스 표현을 사용하되 현재 운영 범위는 [로드맵](roadmap.md)을 따른다. 이번 문서는 이전 리브랜딩 당시의 화면 색 유지 범위를 갱신하며, 명칭·데이터 호환성 원칙은 유지한다.

## 2. 시각 기준

| 요소 | 적용 기준 |
| --- | --- |
| 전체 배경 | off-white `#f6f7f2`, 주요 내용은 밝은 면으로 구분 |
| 기본 글자 | ink `#243b32`, 제목·내용의 크기와 굵기로 순서 표현 |
| 주요 행동·선택 상태 | evergreen `#28624c`, 저장·확인 등 중요한 버튼과 활성 메뉴에 사용 |
| 보조 강조 | 연한 lime `#e5efcf`, 안내·선택 배경에 제한적으로 사용 |
| 모서리·구획 | 반경 10~16px, 얇은 경계와 여백 중심. 과도한 그림자·큰 장식 최소화 |
| 스포츠 표현 | 작은 방패·필드 선 같은 요소를 필요한 곳에 사용하고 정보보다 강조하지 않기 |
| 의미 있는 색 | 공격·미드필더·수비·GK의 기존 색 구분과 오류·성공 상태 유지. 색만으로 의미를 전달하지 않고 텍스트 함께 표시 |

본문·보조 문구·버튼 글자는 배경과 분명히 구분되어야 한다. 터치 영역, 키보드 포커스, 비활성 상태가 부드러운 색 처리 때문에 흐려지지 않도록 실제 화면에서 확인한다.

## 3. 요구사항과 인수 기준

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| DR-R01 | 서비스명과 현재 팀 분리 | 상단에서 조축ON과 현재 팀명을 구분할 수 있다. 긴 팀명·팀 미선택 상태도 겹치지 않으며 특정 팀명을 공통 UI에 고정하지 않는다. |
| DR-R02 | 한 화면씩 탐색 | 선수단을 선택하면 선수단만, 경기 기록을 선택하면 경기 기록만 본문에 표시한다. 활성 메뉴가 명확하고 기존 주소·뒤로가기 이동이 맞는 화면을 가리킨다. |
| DR-R03 | 간결한 코드 접속 | 첫 화면에서 코드 입력·확인 버튼·운영진 로그인 경로를 바로 찾는다. 처리 중·잘못된 코드·접속 제한·세션 만료 안내를 유지한다. |
| DR-R04 | 기존 작업 보호 | 화면 전환이나 선수단 조회 복귀에서 기존 미저장 확인을 유지한다. 입력 초안을 알림 없이 잃지 않고 저장·취소·뒤로의 결과가 구분된다. |
| DR-R05 | 설치 안내의 우선순위 조정 | 설치 안내는 하단에 배치하고 주된 입력을 밀어내거나 고정 버튼을 가리지 않는다. 연결 끊김 경고는 상단에 고정한다. 지원 브라우저 설치·수동 안내·standalone 숨김 정책은 유지한다. |
| DR-R06 | 시각 일관성과 읽기 편의 | 배경·본문·버튼·카드에 시각 기준을 적용하고, 포지션·경고·저장 결과의 의미가 유지된다. 선택 상태와 키보드 포커스를 확인할 수 있다. |
| DR-R07 | 좁은 화면과 기존 기능 | 390px 화면에서 페이지 전체 가로 넘침이나 상단 겹침이 없다. 표는 내부에서 가로 스크롤한다. 정렬·표시 설정과 자동 편성 기준은 펼쳐 확인할 수 있고 선수단·경기 01~04 단계의 기존 기능을 유지한다. |

## 4. 간단 스토리보드

```text
DR-S01 접속
  [조축ON]  조기축구팀 관리
  팀 코드 [                    ]
  [팀으로 들어가기]   [운영진 로그인]
  오류·처리 상태는 입력 근처에 표시
  ... 하단 설치 안내 ...
          ↓ 접속 성공
DR-S02 공통 상단 + 선수단
  [조축ON]                  [계정 메뉴]
  현재 팀: [현재 팀명]      기존 팀 선택 기능
  [선수단 ●] [경기 기록]
  선수단 제목 / 기존 정렬·카드/표·페이지 선택
  작은 화면: [정렬·표시 설정 펼치기]
  선수 목록 또는 선택한 등록·수정 화면
  ... 하단 설치 안내 ...
          ↓ 경기 기록 선택
DR-S03 공통 상단 + 경기 기록
  [선수단] [경기 기록 ●]
  경기 목록 또는 선택한 경기의 입력·상세
  기존 01 투표 → 02 계획 → 03 실제 출전 → 04 결과
  자동 편성 상세 기준은 필요할 때 펼치기
  ... 하단 설치 안내 ...
```

| 화면 | 확인할 상태 | 연결 요건 |
| --- | --- | --- |
| DR-S01 | 코드 접속·운영진 로그인·실패·처리 중·초대 진입의 기존 경로 | DR-R01, DR-R03, DR-R05~06 |
| DR-S02 | 조회/등록/수정, 빈 선수단, 긴 팀명, 회원·운영진, 미저장 상태에서 메뉴 이동 | DR-R01~02, DR-R04~07 |
| DR-S03 | 목록/상세/입력, 단계 이동·저장 결과, 실제 출전·스쿼드의 색과 정보, 뒤로가기 | DR-R02, DR-R04~07 |

서비스 관리자와 팀 미선택 화면도 기존 진입 경로를 유지한다. 예시에 없는 팀 생성·코드 관리·초대 기능을 숨기거나 새 권한을 부여하지 않는다.

## 5. 검증과 완료 상태

- [x] 시각 기준과 DR-S01~03 구현, 가상 데이터 화면 캡처 확인
- [x] 선수단 ↔ 경기 기록 전환과 첫 뒤로가기 확인, 로그인 후 주소 정규화 반영
- [x] 선수 입력 중 이동 취소 시 값 유지·확인 시 이동, 경기 코멘트 수정 중 뒤로가기 취소 시 주소 복원·확인 시 이동 검증
- [x] 390px 화면의 페이지 가로 넘침 없음, 표 내부 스크롤·10명 선택·경기 01~04 단계 표시 확인
- [x] 설치 안내 하단 이동, PWA 아이콘·오프라인 안내 색 통일과 캐시 버전 v2 적용
- [x] `pnpm build`의 TypeScript/Vite 빌드, 프론트 29개 테스트, `git diff --check` 성공
- [ ] 최종 모바일 정렬·표시 접기와 비로그인 화면 추가 확인
- [ ] 사용자가 밝기·친근함·정보 명확성과 주요 작업 동선을 확인

검증은 `localhost:5189`의 독립 예시 서버에서 수행했으며 실제 API·DB·회원 자료에 접속하지 않았다. 390px viewport에서 스크롤바를 제외한 페이지/내용 폭은 375/375px였고 960px 표는 자체 영역에서 가로 스크롤했다. 예시 선수는 가상 자료다. 접속 잠금 시 확인창도 숨김·비활성 처리를 따르도록 별도 body portal 대신 화면 내부에 렌더링하도록 변경했다.
