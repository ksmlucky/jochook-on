# 선수 목록 간소화와 기록 페이지 (2026-10-17 · 운영 반영)

[배포 결과와 최신 검증](release-roster-pagination-2026-10-17.md) · 아래는 구현 당시 검토 기록입니다.

## 범위와 화면 흐름
- 선수단: 휴대폰 2열 카드. 등번호·이름·연령대·직책·1지망과 수정 버튼을 우선 표시한다. 상세 정보에서 생년·연도 기준 나이·1~3지망·가입일을 펼친다. 기존 표 보기와 10/20/30명 페이지는 유지한다.
- 여러 명 입력: 수동 행 입력 → 검토 → 전체 등록. 엑셀 도구는 별도 엑셀 업로드 진입에서만 보여준다. 기존 검증과 저장 API는 그대로다.
- 선수 기록: 기본 20명, 10/20/30명 선택 → 간단 보기 또는 표 보기 → 이전/다음 → 선수 상세 → 같은 페이지로 복귀한다. 검색·정렬·기간/경기 조건·스탯 기준·표시 인원 변경 시 첫 페이지부터 표시한다. 새로고침으로 인원이 줄면 마지막 유효 페이지로 보정한다.
- 전체 결과를 검색·정렬한 뒤 화면에서 페이지를 나눈다. 상단 집계는 전체 조회 범위 기준이며 현재 페이지 인원으로 축소하지 않는다. API/DB와 권한 변경은 없다.
- 팀 접속 관리: 코드·6자리 비밀번호는 발급 직후 1회 표시됨을 명확히 설명한다. 보관하지 않았다면 재발급이 필요하며, 이전 회원 세션 종료 경고를 유지한다. 이번 작업에서 실제 코드 재발급은 하지 않는다.

## 검증
- 프론트 전체 263개 테스트 및 TypeScript/Vite 빌드 성공. 기존 500kB 번들 경고는 남아 있다.
- 가상 선수 47명: 간단 보기 20명 → 2페이지20명 → 표 전환 유지 → 마지막7명 → 상세 왕복 마지막 페이지 유지 확인.
- 검색1명 결과는 첫 페이지, 10명 선택/등번호 정렬 후1~10명 표시. 10/20/30 경계·빈 결과·총합 보존은 테스트 검증.
- 320/390px 가로 넘침 없음, 모바일2열·상세 펼침 확인. 수동 입력에는 엑셀 버튼 없음, 별도 엑셀 진입에는 양식 다운로드 유지 확인.
- 실제 iPhone Safari와 운영 배포는 미실행. 백엔드/MySQL 통합은 변경이 없어 이번 작업에서는 실행하지 않았다. 실제 회원·경기·계정·코드는 변경하지 않았다.
