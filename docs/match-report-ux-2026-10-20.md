# 경기 목록·결과·스쿼드 조회 개편

2026-10-20 11:45 KST · 운영 반영 · 웹·API b6f722a · DB V34

## 목적

사용자가 제공한 참고 이미지처럼 경기 목록은 짧게 읽고, 점수를 누른 뒤 결과 흐름과 스쿼드를 자세히 보는 구조로 바꾼다. 조축ON의 색상·포지션·기존 데이터 기준을 유지한다. 참고 서비스의 로고·선수 사진·광고·분 단위 기록은 복제하지 않는다.

UX 전문가의 지속적인 역할은 [역할 정의](agents/ux-expert.md)에 기록한다. 이 문서는 구현 의도와 인수 기준을 함께 보관한다. 운영 확인 결과는 아래 배포 결과에 기록한다.

## 화면과 주요 행동

| 화면 | 처음 보이는 정보 | 주요 행동 |
|---|---|---|
| 경기 목록 | 날짜, 리그/대회 또는 자체전 구분, 양 팀 이름·로고, 스코어, 작성 상태 | 경기 행 또는 스코어를 눌러 결과 상세 조회 |
| 경기 결과 | 최종 스코어, 경기 정보, 쿼터별 득점·실점 순서와 득점자·도움 | 스쿼드·교체 확인, 목록 복귀; 운영진은 별도 수정 |
| 스쿼드·교체 | 첫 구간 작전판과 교체 관계, 나머지 구간의 접힌 제목 | 각 구간을 독립적으로 펼치기·접기 |
| 팀 로고 관리 | 현재 로고 또는 기본 배지, 이미지 선택 | 운영진이 자기 팀 로고 등록·교체·제거 |

목록에는 장소·포메이션·선수별 득점 긴 문자열을 반복하지 않는다. 기존 10경기 페이지와 조회 조건은 유지한다. 상세에서 돌아와도 선택한 조회 조건과 페이지가 유지되는 것이 목표다. 운영진의 조회와 편집을 분리하며 회원에게 편집 버튼을 노출하지 않는다.

## 모바일 레이아웃

320px와 390px에서 날짜·구분을 위쪽 작은 줄로 놓고, 본문은 `우리 팀 / 스코어 / 상대 팀`으로 구성한다. 팀 로고는 작게 표시하고 미등록 시 팀명 이니셜 또는 기본 배지를 쓴다. 점수 공간을 먼저 확보하고 팀명 영역은 줄바꿈이나 생략을 사용한다. 전체 이름은 상세에서 읽을 수 있어야 한다. 한 행은 최소 44px 터치 영역을 갖는다.

경기 결과는 최종 점수를 먼저 보여 준다. 긴 설명은 타임라인과 스쿼드를 밀어내지 않게 짧게 쓴다. 작전판은 조회 전용으로 보여 주고 선발 아래 교체 선수를 작게 표시한다. 교체가 없는 자리에 빈 교체 칸을 반복하지 않는다. 4쿼터 경기는 첫 진입 시 1쿼터만 열고, 전후반 경기는 전반만 연다. 자체전은 구간 안에 A·B팀을 명확하게 나누며 각 팀 포메이션을 유지한다.

## 득실점 순서의 의미

기존 코드는 `goalEvents`에 골·도움 연결을 저장하고 `goalsAgainst`에 구간 실점 합계를 저장한다. 이 둘만으로 득점과 실점의 선후를 복원할 수 없다. 따라서 다음 원칙을 적용한다.

- 새 순서 기록은 구간 안에서 득점과 실점을 같은 순서 목록으로 취급한다. 사용자가 입력·정렬한 순서에 대해서만 진행 점수를 계산한다. 정확한 분은 요구하거나 추측하지 않는다.
- 외부 경기 실점에는 상대 득점자를 필수로 받지 않는다. 자체전은 A·B팀 득점 방향으로 표시하고 같은 골을 상대 실점으로 중복 저장하지 않는다.
- 이전 기록 또는 합계만 저장한 기록은 `득실점 순서 미기록`으로 표시한다. 골·도움과 실점 합계를 그대로 보여 주며, 임의로 `1:0 → 1:1`처럼 선후를 만들지 않는다.
- 이전 구간 순서나 합계가 불완전하면 이후 타임라인에 확인되지 않은 누적 스코어를 표시하지 않는다. 최종 스코어와 상세 기록 불일치도 감추지 않는다.
- FK·PK는 기존 총 득점의 세부 기록이며 산식과 출전 쿼터 정책은 변경하지 않는다. 기존 선수 통계의 중복 합산이 발생하지 않아야 한다.

## 예외와 상태

| 상태 | 표현과 동작 |
|---|---|
| 확정된 0:0 | `0 : 0`; 득점 없음은 미입력과 구별 |
| 스코어 미입력 | `— : —` 또는 `미입력`; 0:0으로 변환하지 않음 |
| 작성 중 | 작은 `작성 중` 상태; 조회 가능, 통계 포함 기준은 기존 정책 유지 |
| 로딩 | 상세 준비 상태를 알리고 반복 클릭 방지 |
| 조회 실패 | 명확한 오류와 다시 불러오기; 목록 복귀 가능 |
| 저장 중/저장 실패 | 저장 중 중복 요청 방지, 실패 시 입력·선택 순서 유지 |
| 로고 없음/읽기 실패 | 기본 배지와 팀명으로 대체 |
| 긴 팀명·선수명 | 점수/버튼 침범 없이 줄바꿈; 상세에 전체 이름 제공 |
| 라인업 미입력 | 작전판의 미배치 상태와 안내; 실제 선수를 지어내지 않음 |
| 교체 있음 | 선발 → 교체 관계를 텍스트와 기호로 표시; 분 단위 시간 추정 없음 |

## 스토리보드

1. 회원이나 운영진이 경기 기록을 열면 compact 목록에서 날짜와 점수를 훑는다.
2. `예시 FC 2 : 1 상대 FC`를 누르면 결과 상세로 이동한다. 완료·작성 중 상태와 구분을 확인한다.
3. 타임라인에서 `1쿼터 득점 → 1쿼터 실점 → 2쿼터 득점`을 본다. 순서가 기록된 가상 사례이며, 기존 합계 기록에는 같은 순서를 임의로 적용하지 않는다.
4. `스쿼드·교체`로 이동하면 1쿼터가 열린다. 선발과 교체가 있는 자리만 교체 관계를 읽는다.
5. 2~4쿼터 제목을 누르면 필요한 구간만 추가로 연다. 전후반이면 2개 구간, 자체전이면 A·B팀을 구분한다.
6. 운영진은 목록의 `수정` 또는 상세의 `기록 수정`으로 기존 입력 흐름을 열고, 회원은 조회를 계속한다. 홈의 `이어서 작성`은 편집 화면을 바로 연다.

[가상 화면·흐름도](diagrams/match-report/index.html) · [SVG](diagrams/match-report/flow.svg) · [PNG](diagrams/match-report/flow.png) · [생성 소스](../scripts/Generate-MatchReportFlow.mjs). 그림은 가상 화면 설계 예시이며 실제 앱 캡처가 아니다. 생성 명령은 `node scripts/Generate-MatchReportFlow.mjs`이며 PNG 렌더러가 별도 제공되는 환경에서는 `JOCHOOK_SHARP_MODULE`에 Sharp 모듈 경로를 지정한다. SVG를 PNG로 렌더해 세 화면의 텍스트·배치·여백을 확인했다. 실제 앱 동작 검증과는 별개다.

## 인수 기준과 검증 기록

- 320px·390px에서 목록·결과·스쿼드 페이지 가로 넘침 없음, 점수 항상 보임, 긴 이름과 로고 오류에도 읽기 가능.
- 첫 구간만 열린 상태가 초기값이며 각 구간의 접기·펼치기는 독립적이다. 키보드와 확장 상태 안내를 지원한다.
- 완료 0:0 / 미입력 / 작성 중 / 순서 미기록 / 골·도움 연결 없음이 서로 구별된다.
- 4쿼터·전후반·자체전 A/B·6개 포메이션과 교체 관계를 보존한다.
- 결과 조회는 경기 쓰기를 발생시키지 않는다. 팀 로고 변경은 감독만, 경기 기록 수정은 감독·코치만 가능하다.
- 가상 데이터로 테스트하며 실제 선수·경기·계정은 시험 수정하지 않는다.
- 실제 구현·단위 테스트·모바일 렌더 검증 결과는 총괄의 통합 보고에서 확정한다. 이 설계 문서 작성만으로 통과한 것으로 간주하지 않는다.

## 사용자 가이드와 관련 그림 갱신

가이드 1.16 운영진용에는 팀 로고 관리, 결과 조회와 편집 분리, 득실점 순서 입력을 추가했다. 회원용에는 compact 목록 → 결과 타임라인 → 쿼터별 스쿼드 접기·펼치기를 추가했다. 공통 원고·앱 가이드·역할별 HTML/PDF와 공유본의 버튼 이름을 대조하고 회원 7쪽·운영진 21쪽 전체 PDF 렌더를 확인했다. 실제 배포 확인 후 운영 기준 앱 버전과 상태를 확정했으며 PDF 본문 바이트는 배포한 파일 그대로 유지했다.

DB 변경은 담당 개발자가 마이그레이션·ERD를 갱신한다. 시스템·권한 그림은 기존 권한을 유지하더라도 관련 설명을 점검한다. 이 흐름도는 UI 동선이 바뀔 때 생성 소스와 함께 갱신한다.

## 통합 검증 — 배포 전

- 프론트 312개 테스트, TypeScript, Vite 빌드 통과. 번들 크기 경고는 남아 있다.
- 백엔드 단위/API 테스트 통과. 로컬 Docker 엔진이 없어 MySQL 통합 테스트는 GitHub CI에서 확인한다.
- 가상 데이터 모바일 320/390px: 목록·결과·작전판 가로 넘침 없음, 전반 기본 펼침·후반 독립 펼침, 순서 변경→확인→구간 저장→조회, 로고 미리보기·저장을 확인했다.
- 기존 합계 기록의 도움·FK·PK를 보존한다. 최종 스코어와 구간 합계가 다르면 중간 스코어를 숨기고 차이를 안내한다.
- 가이드 1.16 회원 7쪽·운영진 21쪽 전체 렌더와 ERD 7장 렌더 확인.
- 배포 전 암호화 백업을 별도 로컬 MySQL에 복원해 19개 테이블 행 지문을 대조했다. V33·V34 SQL 적용 뒤 원래 컬럼의 값이 동일하고, 과거 경기 순서/팀 로고를 임의 생성하지 않는 것을 확인했다. 격리 복원 자료는 제거했다.
- 실제 iPhone, 운영 자료 쓰기, 운영 로고 업로드는 시험하지 않았다.
