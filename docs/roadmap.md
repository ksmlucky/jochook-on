이번 확장판의 기본 조회는 올해·리그+대회·자체전 포함·완료 기록·회원이며, 이전 기록·작성 중·용병과 외부만/자체전만 조건도 선택한다. 수정·삭제와 완료 상태 변경은 새 조회에 반영하며, 기록 완료 자체가 편집을 잠그지는 않는다. 출석률 분모·가입일·불참/미확인 처리와 시상 동률 기준은 사용자와 별도 합의한다. 기존 자동 편성의 출석률 정책도 이 제안만으로 변경하지 않는다.

회원 공유 코드는 개인을 식별하지 않는다. 초기 개인 기록 조회는 선수 선택으로 제공하고, 회원 직접 투표·개인 알림·내 기록 자동 연결은 개인 계정과 선수 연결 정책을 먼저 설계한다. 지금 사용자가 선택한 운영진 입력·회원 조회 흐름은 유지한다. 경기 요약의 카카오톡 공유는 운영진이 직접 선택하는 기능 후보이며 실제 자료의 공개 링크나 자동 발송을 바로 만들지 않는다.

안정화 후보였던 서버의 동일 저장 요청 중복 방지와 재로그인 후 초안 복원은 2026-10-15 가상 데이터 검증 후 `b9d8738`로 운영 반영했다. 같은 탭·계정·팀의 sessionStorage 초안과 V23 저장 영수증을 사용한다. 브라우저 종료 후 영구 복원과 기기 간 동기화는 범위 밖이다. [현재 동작과 검증 한계](match-draft-recovery.md).

포트폴리오에는 새로운 기술 개수보다 실제 개선 근거를 남긴다. 경기 입력 소요 시간, 저장 오류와 복구 사례, 자동 편성 소요 시간·비선호 배치·출전량 차이, 팀 격리·권한·충돌 테스트, 백업 복원 시간과 배포 복구 결과가 좋은 소재다. 현재 React + 기능별 Spring Boot 단일 애플리케이션 + MySQL 구조를 유지하고, 측정된 문제가 있을 때 캐시·비동기 작업·서비스 분리를 검토한다.

인프라 권장 순서는 **현재 시범 환경 유지 → 자동 백업·복원과 배포 복구 보강 → 실제 사용량·한국 접속 지연 측정 → 예산과 운영 부담에 맞춰 정식 환경 선택**이다. Oracle 자원 확보만으로 이전을 확정하지 않는다. 무료 Sandbox의 용도와 유료 후보 비교는 [배포·인프라 개선 검토](northflank-deployment.md#배포인프라-개선-검토-2026-10-15-제안)를 따른다.

## 운영 범위와 확장 순서 (2026-10-14 확정)

- 당분간 실제 사용 팀은 **HANA FC 한 팀**으로 제한한다. 2026-10-14에는 4-1-2-3 고정 제약 때문에 다른 팀 도입을 보류했고, 이후 6종 포메이션을 구현했다. 지원 확대만으로 다른 팀 도입을 자동 시작하지 않는다.
- 팀 생성·운영진 지정·코드 접속·팀별 데이터 분리는 확장 기반으로 유지한다. 서비스 관리자는 공개 팀 모집을 시작하지 않으며, 개발 검증용 팀은 실제 회원 DB와 분리한 임시 DB에서만 만든다.
- 순서는 **HANA FC 실사용과 운영 피드백 → 포메이션 선택·수동 스쿼드·자동 편성·쿼터 기록·엑셀의 일관된 확장 → 다른 팀 시범 도입**이다.
- 포메이션별 자리·선호 매핑과 기존 기록 호환을 구현·검증했다. 실사용에서 GK 그룹·출전 배분·연속 휴식·교체·출석 우선 결과를 확인하고 다른 팀 시범 도입 여부를 별도로 정한다.
- Oracle Cloud·Cloudflare 배포와 아이폰 접속은 HANA FC의 실사용을 위해 준비하며 다른 팀 공개 시점과 별개다. 이전 AWS 계획에서 변경됐고 Cloudflare 가입은 완료, Oracle 도쿄의 로그인·Free Tier 상태도 확인했다. A1 생성은 용량 부족으로 실패하여 무료 VM 확보와 실제 배포는 미완료다. 도메인은 가격 검토만 허용됐으며 아직 구매하지 않았다.

- [x] 같은 팀 활동 선수끼리 등번호 중복 금지: 등록·수정·일괄/엑셀 검토 및 DB UNIQUE. 번호 미등록은 여러 명 허용, 활동 종료 선수 번호 재사용 가능
- [x] 여러 선수 UI 입력 및 .xlsx 양식 다운로드·업로드·행별 검토·일괄 등록 (최대 200명, 전체 성공 또는 전체 취소)

현재는 소속 팀 운영진 계정으로 로그인해 선수를 등록·수정하고, 선호 순위를 입력하거나 여러 선수를 UI·엑셀로 등록할 수 있다. 회원 계정 발급 화면·비밀번호 운영과 활동 종료 기능은 아직 남아 있다. 이름은 중복을 허용하되 같은 팀 활동 선수의 등번호는 중복을 금지하며, 고정된 선수 ID로 경기 기록을 연결한다. 기본 자동 편성과 외부 용병 등록·재선택을 경기 입력 흐름에 추가했다. 실제 실행 검증 결과는 docs/verification.md를 따른다.

완료 기준: 운영진만 선수를 수정할 수 있고, 회원은 조회할 수 있다. 이미 경기 기록이 연결된 선수를 물리적으로 삭제할지 여부는 이력 정책과 함께 결정한다.
