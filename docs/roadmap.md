- [x] 운영진·회원 역할, 세션 로그인·로그아웃, 서버 권한 검사와 로그인 화면
- [x] 로컬 최초 관리자 생성, BCrypt 비밀번호 저장, 로그인한 계정만 선수 목록 조회
- [ ] 회원 계정 발급·비밀번호 변경과 복구 흐름
- [x] 운영진 전용 선수 등록·수정, 기본 정보 조회와 수정 충돌 처리
- [x] 초기 입력 규칙: 이름 1~60자, 기본 포지션 GK/DF/MF/FW, 등번호 1~99 또는 미등록, 가입일 선택
- [x] 선호 포지션 1·2·3지망 수집: 1지망 필수, 2·3지망 선택, 중복·순서 건너뛰기 금지. 포지션 미확인 UN은 지망 세 칸을 비우며 활동 상태는 유지
- [x] 선택 생년·직책 저장, 현재 연도/경기 연도 기준 연령대를 선수단·참가 명단·쿼터 스쿼드에 표시
- [x] 카드·표 보기, 페이지당 10/20/30명(기본 20명), 전체 명단의 등번호·나이·이름·1지망 포지션 정렬. 기본 등번호 오름차순, 미입력 값은 마지막. 포지션은 GK → 수비 → 미드 → 공격 및 역순, 그룹 내 등번호순
- [x] 직책 정회원/코치/감독/총무/회장 선택, 생년 직접 입력·목록 선택, 수정 중 선수단 보기 이동 시 확인
- [x] 별도 포지션 열을 없애고 1지망에 색 표시: LW/RW/ST 빨강, CM/CDM 초록, LB/CB/RB 파랑, GK 황금색, 미입력 회색. 카드·참석자 선택도 1지망 기준
- [x] 활동 선수끼리 등번호 중복 금지: 등록·수정·일괄/엑셀 검토 및 DB UNIQUE. 번호 미등록은 여러 명 허용, 활동 종료 선수 번호 재사용 가능
- [x] 여러 선수 UI 입력 및 .xlsx 양식 다운로드·업로드·행별 검토·일괄 등록 (최대 200명, 전체 성공 또는 전체 취소)
- [ ] 선수 활동 종료·복귀와 상세 프로필 확장
- [x] 사용자가 제공한 실제 선수 명단 입력 (개인정보는 공개 코드·문서·샘플에 포함하지 않음)

현재는 로컬 관리자 계정으로 로그인해 선수를 등록·수정하고, 선호 순위를 입력하거나 여러 선수를 UI·엑셀로 등록할 수 있다. 회원 계정 발급 화면·비밀번호 운영과 활동 종료 기능은 아직 남아 있다. 이름은 중복을 허용하되 활동 선수의 등번호는 중복을 금지하며, 고정된 선수 ID로 경기 기록을 연결한다. 기본 자동 편성과 외부 용병 등록·재선택을 경기 입력 흐름에 추가했다. 실제 실행 검증 결과는 docs/verification.md를 따른다.

완료 기준: 운영진만 선수를 수정할 수 있고, 회원은 조회할 수 있다. 이미 경기 기록이 연결된 선수를 물리적으로 삭제할지 여부는 이력 정책과 함께 결정한다.

## 2단계 — 경기 중심의 투표·출석·기록 입력

사용자 요청에 따라 별도 모임 등록보다 경기 기록을 먼저 구현한다. 카카오톡 참불 투표는 운영진이 직접 옮겨 적고, 경기 후 실제 출석과 기록을 보완한다. 자동 카카오톡 연동은 하지 않는다.

- [x] 경기 날짜·필수 시작 시간(30분 단위)·선택 장소·상대 팀·경기 후 코멘트 등록, 목록·상세 조회와 수정
- [x] 4쿼터 합계 스코어 직접 입력, 미입력/0:0 구분, 선수 득점 합계와 차이가 나면 안내하되 저장 허용
- [x] 목록 10개씩 페이지, 스코어와 실제 득점자 등번호 오름차순 최대 3명·외 N명, 번호 없는 선수는 마지막
- [x] 시작 시간 + 2시간으로 경기 시간대 표시, 자정 경계는 다음 날 표시. 종료·쿼터 길이는 별도 저장하지 않음
- [x] 01~04 단계 탭, 단계 이동 시 초안 유지, 하단 고정 저장 버튼으로 스크롤 줄이기
- [x] 시작 시·분 별도 선택(00~23시, 00/30분), 단계·최종 저장 성공 시 반투명 알림을 4초간 표시
- [x] 선수별 참석 예정·불참 예정·미정·미투표와 실제 참석·지각·불참·미확인을 독립 저장
- [x] 이름·등번호 검색과 체크로 참석 투표 명단 선택, 선택한 선수만 보기
- [x] 참석 예정자 1~4쿼터 계획 스쿼드: 드래그/클릭 배치·자리 교환·이전 쿼터 복사·0.5쿼터 계획 합계. 실제 출석/출전과 분리 저장
- [x] 03 시작의 계획대로 저장: 참석 예정·미확인을 참석으로, 계획을 실제 출전으로 한 번에 DB 저장. 지각·불참 유지, 계획의 실제 불참자 검사, 기존 실제 출전이 하나라도 있으면 덮어쓰기 차단
- [x] 02에서 용병 등록·재선택: 이름 필수, 등번호·생년·선호 선택, 회원과 구분, 자동 편성·실제 경기 기록 연결
- [x] 고정 1~4쿼터·4-1-2-3의 실제 출전 명단 직접 배치 (쿼터 길이는 저장하지 않음)
- [x] 같은 자리의 선발 1명 ↔ 교체 1명 기록: 두 선수 각 0.5쿼터, 교체 없는 선발 1쿼터로 집계
- [x] 4쿼터 엑셀 양식 다운로드·행별 검토·초안 반영: 포지션·이름·선택 등번호·득점·도움·선발/교체
- [x] 선수별 쿼터 출전·득점·도움 저장과 해당 경기의 입력 기록 집계
- [x] 투표만 먼저 저장한 뒤 기록 보완, 중복 배치·불참자 출전 방지, 전체 트랜잭션 저장과 version 수정 충돌 검사
- [ ] 실제 경기 한 건을 운영진이 입력하고 원본과 대조
- [ ] 쿼터 수 변경, 경기 기록 확정과 미확인 득점 구분
- [ ] 한 날짜의 여러 상대 경기를 모임 단위로 묶기, 모임 기준 출석 집계
- [x] 하루 4쿼터 전체 자체전: 경기 단위 외부 경기/자체전 유형, 쿼터별 A팀·B팀 각각의 4-1-2-3 계획·실제 배치와 최종 A:B 합계 스코어
- [x] 자체전에서도 선수 고유 ID 유지, 같은 쿼터 양 팀 중복 배치 금지, 쿼터별 팀 변경 허용, 경기당 출석 한 번과 팀별 교체 출전량 계산
- [x] 자체전 양 팀 계획→실제 기록 일괄 복사, 팀별 엑셀 반영, 목록의 자체전·팀별 득점자 표시
- [ ] 자체전 자동 편성 시 두 팀의 선호 포지션·GK·출전량 균형 검토. 현재 외부 경기용 편성 정책을 그대로 적용할지는 별도 결정
- [x] 자체전 득점·도움·출전 기록을 경기 유형으로 구분해 보관
- [ ] 자체전의 시즌 순위·연말 시상 포함 여부 결정, 필요 시 쿼터별 수동 스코어 추가 (현재는 4쿼터 합계)
- [ ] 서버의 신규 경기 중복 요청 방지 (현재 UI 연타·응답 불명 시 재전송 차단)

현재 4쿼터는 고정이며 길이·교체 시각은 저장하지 않는다. 교체는 같은 자리의 1:1 교체만 지원하고 재투입·같은 쿼터의 포지션 이동은 지원하지 않는다. 비어 있는 배치 자리는 미기록으로 남긴다. 엑셀 반영은 기존 4쿼터 초안을 교체하며 투표·실제 출석을 자동 변경하지 않는다. 자동 편성은 경기 전 계획만 채우고 분 단위 추정·프로 환산은 하지 않는다. 참석자의 출전 명단이 없어도 실제 출석은 보관한다.

완료 기준: 실제 모임 하루의 기록을 운영진이 입력하고, 화면의 개인 집계가 원본 기록과 일치한다.

## 3단계 — 시즌 통계와 재미 요소

- 득점·도움·출석 순위, 최소 참가 기준과 동률 규칙
- [ ] 선수 명단의 득점·도움·출전 쿼터 수 정렬: 선택한 시즌/기간의 누적값, 1:1 교체의 각 0.5쿼터 반영, 동률 처리와 기록 없는 선수 표시 기준 결정
- 연말 시상 결과 확정, MVP 선정 방식
- 포지션별 기여를 고려한 가상 몸값 산정과 변동 이력

완료 기준: 수치의 근거를 확인할 수 있고, 기록 정정 시 재집계 규칙이 일관되다.

## 4단계 — 실제 운영과 포트폴리오

- [x] Docker 배포 이미지·별도 운영 Compose·HTTPS 프록시 구성, Git/이미지에서 개인정보·로컬 DB 제외
- [ ] 무료 호스팅 계정과 실제 자원 한도 확인 후 배포 (Northflank Sandbox / Oracle Always Free 우선 검토, 특정 공급자로 확정하지 않음)
- [ ] 운영진 전용 회원 공유 코드 발급·재발급·폐기, 회원은 코드로 바로 조회, 이전 코드와 세션 무효화
- [ ] 타 팀 확장 시 팀별 데이터 분리와 운영진 소속 검증, 팀별 공유 코드 (현재는 HANA FC 한 팀)
- 자동 배포, 로그·알람, DB 백업·복구 확인
- 동시 수정 처리, 조회 성능 측정과 개선 기록
- 실제 사용자 피드백에 따른 개선
- 필요한 경우 카카오톡·메모를 입력 초안으로 변환하고 운영진이 검토

포트폴리오에는 기능 소개뿐 아니라 요구사항, 설계 선택 이유, 문제 재현, 검증 결과, 개선 전후 수치를 남긴다. Redis·Kafka·Kubernetes·Spring Batch는 해결할 문제가 생겼을 때 도입 근거를 검토한다.

## 자동 편성 — 경기 입력 단계로 앞당겨 구현

사용자 요청에 따라 기본 자동 편성을 경기 기록 입력 흐름에 추가했다. 자세한 정책과 계산 구조는 [자동 편성 설명](automatic-lineup.md)을 따른다.

- [x] 참석 예정 명단 확인 버튼으로 1~4쿼터 4-1-2-3 계획 자동 생성
- [x] 1~3지망 중 GK가 있는 선수를 GK 전용 그룹으로 분리, 한 명이면 4쿼터 전담
- [x] 같은 쿼터 중복 출전 금지, 같은 자리 1:1 교체는 각각 0.5쿼터
- [x] 두 쿼터 연속 휴식 금지, 그룹 내 총 출전량 차이 최대 1쿼터
- [x] 1~3쿼터 교체 최소화 우선, 필요한 교체는 4쿼터에 우선 배치
- [x] 남는 출전량은 과거 실제 출석률 순으로 배정, 동률은 추첨
- [x] 선호 100/60/30 점수, CB·CM 두 자리 대응, 비선호 배치 알림
- [x] 출석률·개인 출전량·휴식·쿼터별 교체 수 표시
- [x] 기존 계획 교체 확인, 드래그 수동 수정, 실제 출석·기록과 별도 저장
- [x] 인원 부족/GK 없음/포지션 미확인/계산 시간 제한 경고와 단위·MySQL 검증

## 5단계 — 마지막 기능 확장

### 5-1. 자동 편성 고도화

- [ ] 선수별 가능한 쿼터, 고정 배치와 당일 참석 변경 반영
- [ ] 대회 기준 연도와 연령대별 정원 (생일 없이 기준 연도 − 생년)
- [ ] 다른 포메이션, 가중치 조절, 시즌/최근 기간 출석률 정책
- [ ] 편성 근거·정책 버전·시드·출석률 스냅샷 영구 저장과 재현
- [ ] 후보 비교와 포지션 최적화 성능 개선

선호 선택지는 LB/CB/RB/CDM/CM/LW/ST/RW/GK를 유지하며 선호 미확인은 임의로 추정하지 않는다. 현재 인원 전체를 참석 처리하지 않고 운영진이 실제 투표 명단을 선택한다.
### 5-2. 프로 선수와 기록 비교 (가장 마지막)

- [ ] **출전 4쿼터 = 비교용 1경기**를 후보로 검토. 아직 확정·구현하지 않으며 기존 2쿼터=45분 초안은 적용하지 않음
- [ ] 팀 경기 수와 선수 개인의 출전량 중 어떤 분모를 쓸지 결정. 현재 개인 기록은 교체한 두 선수 각각 0.5쿼터로 보존
- [ ] 확정한 기준에 따라 프로 선수의 90분 경기당 득점·도움과 비교할 지표 설계. 쿼터 길이·실제 출전 분은 수집하지 않음
- [ ] 비교 화면에 출전 쿼터, 적용 기준과 비교 기간을 함께 표시하고, 경기 수준 차이를 고려한 재미용 기록 비교로 설명
- [ ] 프로 선수 기록의 데이터 출처·이용 조건·갱신 주기와 최소 출전량 기준 결정

완료 기준: 실제 기록을 보존하면서 환산 근거를 확인할 수 있고, 같은 기간·지표 기준으로 조기축구 선수와 프로 선수의 기록을 비교할 수 있다. 출전량이 0이거나 불명확한 경우에는 환산 지표를 계산하지 않는다.

## 외부 용병 참가 — 기본 구현과 후속 정책

인원이 부족하면 외부 용병을 초청해 경기를 진행할 수 있다. 사용자 요청에 따라 02에서 등록·재선택하는 기본 흐름을 구현했다.

- 용병은 실제 경기에 참가하는 외부 참가자이며, 테스트용 더미 데이터로 처리하지 않는다.
- 이름은 있지만 등번호는 없는 상태로도 참가할 수 있어야 한다. 없는 등번호에 임의의 번호를 부여하지 않는다.
- [x] MEMBER/GUEST 구분과 같은 ID 재참가, 회원 목록에서 분리, 선호 기반 자동 편성·경기 기록 연결
- [ ] 용병 전용 프로필 수정·활동 종료, 회원 전환과 동명이인 병합 정책
- 출석·시즌 순위·시상·가상 몸값에 포함할지는 별도 정책으로 결정한다.
