# 감독·코치 권한 요구사항과 화면 흐름

작성일: 2026-10-14. 사용자 요청에 따른 기능을 로컬 앱과 V18 DB에 적용했다. 실제 실행 범위와 제한은 [검증 기록](verification.md)을 따른다. 기존 [팀 접속 요구사항](team-access-requirements.md)의 공통 운영진 권한을 아래 감독·코치 정책으로 구체화한다. 계정·팀 분리, 코드와 팀 비밀번호, 초대 24시간 정책은 유지한다.

## 1. 목적과 범위

선수·경기 기록은 해당 팀의 감독 또는 코치가 개인 계정으로 등록·수정한다. 감독은 본인 팀의 코치를 임명하거나 해제한다. 서비스 관리자는 팀을 생성하고 최초 감독을 지정하며, 서비스 관리 권한만으로 팀 기록을 수정하지 않는다.

선수 명단의 `직책`은 실제 동호회 활동 정보다. 로그인 계정의 팀 소속 권한과 자동 연결하지 않는다. 이름·등번호·직책을 바꿔도 로그인 권한이 바뀌지 않으며, 선수 등록만으로 개인 계정이 생성되지 않는다. 선수와 계정 연결, 감독의 다른 감독 임명, 이메일 자동 발송은 이번 범위에서 제외한다.

## 2. 권한 표

| 작업 | 팀 코드 접속 / MEMBER | COACH · 코치 | DIRECTOR · 감독 | 서비스 관리자 권한만 보유 |
| --- | --- | --- | --- | --- |
| 선수·경기 조회 | 현재 팀 | 현재 팀 | 현재 팀 | 해당 팀 조회 소속이 있어야 가능 |
| 선수·용병 등록/수정, 일괄 입력, 엑셀 업로드 | 불가 | 현재 팀 | 현재 팀 | 불가 |
| 경기·계획·실제 출전·결과 등록/수정, 자동 편성·엑셀 입력 | 불가 | 현재 팀 | 현재 팀 | 불가 |
| 회원용 팀 코드·비밀번호 발급/재발급/폐기 | 불가 | 현재 팀 | 현재 팀 | 불가 |
| 코치 목록·임명·초대·해제 | 불가 | 불가 | 현재 팀 | 서비스 팀 관리에서 감독/코치 지정·소속 해제 가능 |
| 새 팀 생성·감독 지정/소속 해제 | 불가 | 불가 | 불가 | 가능 |

서비스 관리자에게도 팀 소속 권한이 있으면 그 역할의 기능을 함께 사용할 수 있다. 감독·코치는 복수 팀 소속이 가능하지만 현재 선택한 팀의 역할만 적용한다. `회장`, `총무`, `정회원` 등 선수 직책으로 쓰기 권한을 추정하지 않는다.

## 3. 요구사항

| ID | 구현 기준 | 인수 기준 |
| --- | --- | --- |
| TS-R01 | 개인 계정의 활성 팀 소속 역할을 DIRECTOR / COACH / MEMBER로 구분한다. 기존 ADMIN 소속은 COACH로 이전한다. 기존 계정의 비밀번호·서비스 관리 플래그는 보존한다. | A01·A02 |
| TS-R02 | 선수·경기의 모든 변경 진입점에서 감독/코치 여부를 검사한다. 화면 버튼 숨김과 별도로 서버에서도 거부한다. | A03·A04 |
| TS-R03 | 감독만 현재 팀의 코치 관리에 접근한다. 다른 팀의 계정·소속·초대 ID를 보내도 조회/변경하지 않는다. | A05·A06 |
| TS-R04 | 감독이 정확한 로그인 ID를 입력하면 활성 계정을 현재 팀 코치로 임명한다. 이미 코치면 중복 소속을 만들지 않는다. MEMBER 또는 해제한 소속은 코치로 활성화할 수 있다. | A07 |
| TS-R05 | 새 계정이 필요한 코치는 감독이 24시간 일회용 초대를 발급한다. 링크는 감독이 개인 전달하며, 수락자가 비밀번호를 직접 설정한다. 기존 ID는 해당 계정으로 로그인한 뒤 수락한다. | A08 |
| TS-R06 | 코치 초대의 대상 역할은 서버가 COACH로 고정한다. 직접 임명은 감독 소속을 변경하지 않는다. 초대 수락은 기존 활성 DIRECTOR의 역할을 유지하며, 비활성 DIRECTOR를 코치 초대로 다시 연결할 때는 COACH만 부여한다. | A09 |
| TS-R07 | 코치 해제는 현재 팀의 역할을 MEMBER로 변경한다. 해당 팀 조회와 다른 팀의 소속은 유지하며, 이후 쓰기 요청은 거부한다. 개인 비밀번호·다른 팀 권한은 바꾸지 않는다. | A10 |
| TS-R08 | 감독은 현재 팀의 미사용 코치 초대를 재발급·취소할 수 있다. 재발급 전 링크, 취소·만료·사용된 링크로 소속 권한을 새로 부여하지 않는다. 감독 초대는 코치 관리에서 변경하지 않는다. | A08·A09 |
| TS-R09 | 서비스 관리자의 팀 생성·감독 지정은 DIRECTOR를 부여한다. 마지막 활성 감독의 소속 해제를 막으며, 활성 코치나 미수락 감독 초대는 대체 감독으로 세지 않는다. | A11 |
| TS-R10 | 매 요청에 활성 계정·활성 팀 소속·현재 팀을 다시 확인한다. 역할 변경 뒤 오래된 화면에서 보내는 변경 요청도 최신 권한을 적용한다. CSRF·팀 전환 방어는 유지한다. | A06·A10·A12 |

기존 ADMIN을 COACH로 바꾸는 것은 기존 편집 기능을 유지하면서 새 감독 임명 권한을 일괄 부여하지 않기 위한 이전 정책이다. 사용자는 초기 감독 계정 결정을 총괄에게 위임했고, 현재 유일한 로컬 초기 관리자 계정을 해당 팀의 첫 DIRECTOR로 명시적으로 지정하기로 했다. 이 결정은 모든 기존 관리자를 자동 승격하는 규칙이 아니다. 이후 서비스 관리 화면에서 실제 운영할 감독을 초대·활성화한 뒤 권한을 인계할 수 있다.

기존 운영진 초대는 COACH로 이전한다. 초대 확인·수락 시 발급자가 현재 활성 서비스 관리자이거나, COACH 초대라면 해당 팀의 활성 DIRECTOR여야 한다. 발급자가 그 권한을 잃으면 남은 기간이 있어도 사용할 수 없으며, 현 감독 또는 서비스 관리자가 재발급해야 한다. 재발급 시 발급자를 현재 담당자로 갱신한다.

## 4. 화면 흐름

### TS-S01 · 접속 상태와 편집

개인 로그인 → 팀 선택 → 팀명과 `감독` / `코치` / `조회` 표시 → 권한에 맞는 선수·경기 버튼 표시.

- 감독·코치에게 기존 등록/수정 동선을 제공한다. 조회 회원에게 편집 메뉴를 보여 주지 않는다.
- 감독에게만 `코치 관리`를 제공한다. 선수 직책 수정 화면에는 직책이 로그인 권한과 별개임을 짧게 안내한다.
- 화면 사용 중 권한이 바뀌면 저장 성공으로 표시하지 않고 최신 접속 상태를 확인하도록 안내한다.

### TS-S02 · 감독의 코치 관리

```text
현재 팀 · 코치 관리
코치에게 선수·경기 등록 및 수정 권한을 부여합니다.
선수 명단의 직책과 로그인 권한은 별개입니다.

[기존 계정 임명]  [새 코치 초대]

로그인 ID              권한     상태       작업
예시 계정              코치     활성       [코치 해제]

초대 대상 표시명       권한     유효기간   작업
예시 초대              코치     ...        [재발급] [취소]
```

- 기존 계정 임명: 로그인 ID 입력 → 팀·대상·부여할 권한 확인 → 저장 → 목록 갱신 및 자동으로 사라지는 완료 알림.
- 새 코치 초대: 표시명 입력 → 초대 발급 → 링크와 만료 시각을 한 번 표시 → 복사·닫기. 개인 전달 안내를 표시하며 자동으로 메일을 보내지 않는다.
- 코치 해제: 대상과 `선수·경기 수정은 불가하고 조회는 유지됩니다` 안내 → 확인 → MEMBER 전환. 다시 임명하려면 기존 계정 임명을 사용한다.
- 초대 재발급/취소: 기존 링크가 무효가 됨을 먼저 알린다. 사용된 초대는 취소 대신 해당 코치의 권한을 해제하도록 안내한다.
- 감독 계정은 코치 해제 대상으로 제공하지 않는다. 계정 비밀번호 변경은 이 화면에 포함하지 않는다.

### TS-S03 · 코치 초대 수락

개인 전달받은 링크 열기 → 초대 팀·코치 역할·만료 시각 확인 → 새 ID/비밀번호 설정 또는 기존 계정 로그인 → 수락 → 해당 팀 코치로 접속.

- 초대 원문은 링크 fragment를 읽은 후 주소에서 제거하고 브라우저 영구 저장소·로그에 남기지 않는다.
- 오류가 나도 계정 비밀번호를 덮어쓰거나 소속을 부분 저장하지 않는다.
- 대상이 이미 감독이면 권한을 코치로 낮추지 않는다.

### TS-S04 · 서비스 관리자의 감독 지정

팀 관리 → 새 팀 생성 또는 기존 팀 선택 → 기존 계정 감독 지정 / 감독 초대 → 활성 감독 확인.

- 팀 생성·감독 지정 화면에는 부여되는 역할이 `감독`임을 명시한다.
- 기존 팀은 사용자 위임에 따라 결정한 로컬 초기 관리자 계정 하나를 첫 감독으로 지정한다. 신규 환경에서 모든 ADMIN 소속을 자동으로 감독으로 승격하지 않는다.
- 마지막 활성 감독을 해제하려 하면 대체 감독의 활성화가 먼저 필요하다고 안내한다.

## 5. 입력·상태 처리

| 상황 | 화면 처리 |
| --- | --- |
| 로그인 ID가 비었거나 기존 형식에 맞지 않음 | 해당 입력에 오류 표시, 요청하지 않음 |
| 존재하지 않거나 비활성 계정 | 지정할 계정을 확인하도록 안내, 권한 변경 없음 |
| 이미 코치인 계정 재지정 | 중복 계정/소속 없이 현재 상태 표시 |
| 감독을 코치로 지정/해제하려는 요청 | 감독 권한은 코치 관리에서 변경할 수 없다고 안내 |
| 코치/회원이 감독 작업 시도 | 서버 거부, 성공 알림 없음 |
| 다른 팀의 소속/초대 ID 사용 | 해당 리소스를 찾을 수 없다는 일반 오류, 타 팀 정보 표시 없음 |
| 저장 중 중복 클릭 | 버튼 비활성화, 결과 뒤 목록 갱신 |
| 네트워크 오류 또는 결과 불명 | 상태 재조회 후 재시도, 임명/발급 성공을 추정하지 않음 |
| 초대 원문 복사 실패 | 직접 선택·복사 가능, 자동으로 창을 닫지 않음 |

모바일에서도 팀명·역할·대상·확인 버튼을 읽을 수 있어야 한다. 키보드로 임명/초대/해제 동선을 사용할 수 있도록 입력 레이블과 버튼 이름을 제공한다. 완료 알림은 보조 안내이며 결과 목록이 실제 상태를 보여 준다.

| TS-A13 | 초대 발급자의 계정 비활성화·서비스 관리 권한/감독 소속 상실 뒤 미사용 초대 수락 | 유효기간이 남아도 거부, 현 권한자가 재발급한 초대는 수락 가능 |

## 7. 운영 결정과 후속 작업

- 초기 감독 계정은 사용자의 위임에 따라 현재 유일한 로컬 초기 관리자 계정으로 결정했다. 계정명과 인증 정보는 공개 문서에 남기지 않는다. 실제 적용·검증 결과는 검증 기록을 따른다.
- 최초 감독을 나중에 인계할 경우 새 감독 계정을 활성화한 다음 기존 감독 권한을 조정한다. 미수락 초대만 발급한 상태에서는 마지막 감독을 해제할 수 없다.
- 실제 선수의 등번호 충돌 해결은 별도 데이터 입력 건이다. 코치 권한 기능을 위해 기존 선수를 덮어쓰거나 비활성화하지 않는다.
