# 골·도움 연결 기능 배포 재개 기록

2026-10-19 사용자가 로컬 작업 완료 후 배포를 승인했다. 아래 대기 사유와 재개 순서는 당시 기록이다. 이후 웹·API `dd29444`, DB V31, 가이드 1.9 운영 배포를 확인했다. [최종 검증 결과](goal-events-mobile-2026-10-19.md#2026-10-19-운영-배포-결과)를 참조한다.

## 구현과 확인

[기능 명세·검증 범위](goal-events-mobile-2026-10-19.md). 골별 득점·도움 연결, 서버 합계 계산, 기존 자료 보존, V31 마이그레이션, 모바일 자리 선택과 고정 저장 버튼, 알림 페이드, 개인 계정 7일 idle 세션을 로컬에 준비했다.

백엔드 단위/API 485개, 별도 native MySQL 8.4 검증 10개, 신규 프론트 로직 6개, 최신 TypeScript 검사가 통과했다. 기존 운영 DB에 쓰기 테스트를 하지 않았다.

## 배포를 진행하지 못한 이유

사용자의 배포 승인 후 정식 도구로 재시도했으나 전체 프론트 테스트·최종 빌드와 브라우저 미리보기 실행이 자동 승인 검토에서 실행 전 차단됐다. 도구 원인은 `Selected model is at capacity`이며 위험한 작업으로 판정된 것이 아니라 검토 자체가 완료되지 않은 오류다. 승인 경로를 우회하지 않았고 클라우드 변경·백업·DB 마이그레이션·배포는 실행하지 않았다. 사용자에게 배포 승인을 다시 받을 필요는 없다. 도구 정상화 후 이미 승인된 범위에서 계속한다.

## 재개 순서

1. 기존 로컬 변경을 보존하고 `git status`와 이 명세를 확인한다. `scripts/database-schema.mjs`는 별도 기존 미추적 파일이므로 임의 포함하지 않는다.
2. 전체 프론트 회귀 테스트·최종 빌드 실행. 가상 데이터로 320/390px 작전판 선택/교체/자리 교환, 스크롤 유지, 고정 버튼, 골 추가/도움 변경/삭제/과거 합계 전환과 알림 페이드를 확인한다.
3. 운영진·회원 가이드 1.9의 버튼/절차 및 모든 PDF 페이지·앱 목차/PDF 연결 확인. 배포 전 상태는 pending_deployment로 유지한다.
4. 검증한 변경을 Git에 반영하고 GitHub CI의 단위/API·MySQL·프론트 결과를 확인한다.
5. 기존 승인된 Northflank 인증 범위를 확인한다. 기존 무료 자원 유지. 운영 V30 백업을 생성·격리 복원 검증하고 배포 직전 스냅샷을 보존한다.
6. API 쓰기 경합을 방지한 상태에서 API V31 적용·이전 테이블 자료 보존 확인 후 웹을 갱신한다. 이미 골별 기록이 생긴 뒤 이전 API로 단순 롤백하면 연결/합계 불일치가 생길 수 있으므로 API만 임의 롤백하지 않는다.
7. 공개 HTTPS·배포 커밋·자산 해시·로그인/조회·권한과 가이드 반영을 검증한다. 실제 팀 자료를 쓰기 테스트 대상으로 사용하지 않는다. 가상 DB의 쓰기 검증과 운영 읽기 검증을 구분해 보고한다.
8. 운영 확인 후 가이드 기준·배포 문서·다이어그램의 운영 상태를 확정하고 휴대폰 확인 주소를 전달한다.

## 사용자 요청에 따른 재시도

2026-10-19 사용자 요청으로 전체 프론트 테스트와 최종 빌드를 정식 승인 경로에서 다시 시도했다. 명령 실행 전 자동 승인 검토가 동일한 Selected model is at capacity 오류로 실패했다. 테스트·빌드는 이번 시도에서 실행되지 않았고, Git push·백업·마이그레이션·배포도 수행하지 않았다. 기존 검증 결과와 로컬 변경은 보존했다.

## 한도 초기화 후 재개

같은 날 Codex 5시간 사용량이 초기화된 뒤 전체 프론트 276개 테스트와 TypeScript·Vite 최종 빌드가 통과했다. 가상 데이터 390px·320px 브라우저에서 작전판 자리 선택, 교체, 스크롤 복귀, 저장 버튼과 기존 득점 연결 화면을 확인했다. 승인된 네트워크 경로에서 공개 HTTPS 읽기 전용 점검 9개가 통과했다. GitHub 반영·새 운영 백업·V31 적용·배포는 이 시점에는 아직 수행하지 않았다.

## 재개 후 완료

커밋 `dd29444`를 GitHub에 올려 [CI](https://github.com/ksmlucky/jochook-on/actions/runs/39223337706) 성공을 확인했다. 운영 V30 암호화 백업과 격리 복원·행 지문 대조 후 Northflank에서 새 API·웹 이미지를 빌드했다. `disabledCI=true`였지만 두 서비스가 빌드 성공 후 자동 적용되는 설정이었다. API·웹이 정상 기동했고, DB V31 및 기존 자료 보존, 공개 HTTPS와 운영진 읽기·권한, JS/CSS/PDF 바이트 일치를 확인했다. 실제 iPhone·운영 자료 쓰기 검증은 하지 않았다.
