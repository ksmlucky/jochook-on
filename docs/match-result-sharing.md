# 경기 결과 이미지 공유

2026-10-20 15:45:18 KST · 운영 반영 9b443ff

## 목적과 흐름

경기 결과를 확인한 운영진과 회원이 최종 스코어·득점자·도움을 PNG 한 장으로 공유한다.

경기 기록(또는 홈 최근 경기) → 경기 결과 → `결과 이미지` → 미리보기 → `이미지 공유` 또는 `PNG 다운로드`.

- 경기 상세가 읽어 온 저장된 기록만 사용한다. 편집 중인 초안은 포함하지 않는다.
- 완료·작성 중·기존 상태 미지정을 이미지에 구분한다. 미입력 점수는 `—`이며 0점으로 대체하지 않는다.
- 골 이벤트가 있는 구간은 이벤트를 기준으로 집계하고, 없는 기존 구간만 선수별 합계 기록을 사용한다. 빈 이벤트 배열도 기록된 0개로 취급한다.
- 선수별 골·도움은 구간 전체를 합산한다. 자체전은 A팀과 B팀을 분리한다. 상대 선수의 이름이나 골·도움은 추측하지 않는다.
- 수동 최종 스코어와 선수별 합계가 다르면 원래 값을 유지하고 안내한다. 골과 도움의 연결이나 시각을 새로 만들어 넣지 않는다.
- 선수 이름·등번호만 포함하며 생년·계정·접속 코드·비밀번호·메모는 이미지에 넣지 않는다.
- 파일 공유가 가능한 기기는 운영체제 공유 창을 사용한다. 전송 대상은 사용자가 선택하며 앱에서 자동 전송하지 않는다.
- 공유 취소는 취소 안내로, 공유 실패는 PNG 다운로드 대체 경로로 안내한다.
- 이미지 생성 중에는 진행 상태, 실패 시 다시 만들기를 제공한다. 닫을 때 임시 이미지 URL을 해제하고 원래 버튼으로 포커스를 돌려준다.

## 구성과 호환성

기존 스쿼드 이미지의 브라우저 내 SVG→PNG 변환과 파일 공유 감지를 재사용한다. 결과 이미지는 내용 길이에 맞는 높이를 사용한다. API·DB·권한·집계 정책과 기존 스쿼드 이미지 크기(1080×1480)는 바뀌지 않는다. 외부 이미지 생성 서비스나 저장소를 추가하지 않는다.

UI 담당은 이미지 디자인과 순수 집계 모듈, UX 담당은 상태·공유 흐름과 회원/운영진 핵심 가이드를 검토한다. 가이드 1.19는 회원 3쪽·운영진 6쪽을 유지한다.

[실제 생성 모듈로 만든 가상 이미지·흐름](diagrams/result-sharing/index.html) · [생성 스크립트](../scripts/Generate-MatchResultShare.mjs).
