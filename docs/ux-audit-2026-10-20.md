## 결론

경기 입력, 통계, 초안 복원 등 기능은 갖춰져 있지만 모바일에서는 **결과를 보기 전에 지나야 하는 메뉴·설명·설정의 높이**가 크다. 이번 작업은 기능을 추가하는 대신, 첫 결과까지의 거리를 줄이고 현재 화면에서 해야 할 행동을 분명하게 만든다. 통계 산식·권한·실제 경기 데이터는 바꾸지 않는다.

## 이번 로컬 수정

### 선수 기록

- `StatsSection.tsx`, `stats.css`.
- 기본 조회 기간과 경기 조건은 기존 필터에 그대로 표시한다. 중복된 페이지 소개·범위 설명만 제거했다.
- 이미 존재한 모바일 3열 요약의 여백·단위 줄바꿈을 줄였다. 집계 경기의 매칭/자체전 횟수와 득점/실점 범위 표시는 유지한다.
- `집계 내역`을 접어 실점 합산의 상세 설명을 옮겼다. 완료/이전/작성 중 건수는 접힌 상태에서도 보인다.
- 실점 미입력 제외 건수와 작성 중 집계 변동 경고는 펼치지 않아도 보인다.
- `보기 설정`에 누적·1~4쿼터당 기준, 정렬, 페이지당 인원을 모았다. 기본 10명, 표 제목 정렬, 검색 및 모든 집계 방식은 그대로다.
- 잘못 남은 `03 실제 출전` 안내를 현재 단계명인 `03 결과·코멘트`로 맞췄다.

### 팀 홈

- `HomeSection.tsx`, `home.css`.
- 작성 중인 경기가 없을 때 큰 빈 이어쓰기 카드를 제거했다.
- 최근 경기 아래에 “최근 10경기에 작성 중인 기록이 없어요. 저장 전 초안은 경기 기록 화면에서 복원하세요.”를 작게 표시한다.
- 작성 중인 기록이 있으면 이전과 동일하게 최대 2개를 먼저 보여 준다.

공통 헤더·관리 화면·경기 상세 제목은 총괄 담당, 타임라인·상세의 시각적 접근성은 UI 담당이 각각 수정한다. 이 문서만으로 해당 변경의 검증이나 운영 반영이 끝났다고 간주하지 않는다.

### 팀 로고의 미저장 보호

- 독립 화면 전환 리뷰에서 로고 파일 선택과 전역 이탈 보호의 연결이 빠져 있음을 확인했다.
- `TeamLogoManager.tsx`에 `useEditGuard(file !== null, busy)`를 연결했다.
- 파일 선택 후 이동은 확인을 거치고, 업로드·삭제 처리 중에는 이동을 막는다. 성공하면 보호를 해제하고 실패하면 선택 파일을 유지한다.
- 가상 서버는 업로드를 지원하지 않아 실제 업로드 성공 뒤 이동은 이번 담당 검증에서 실행하지 않았다.

## 잘 되어 있는 부분

- **조회와 편집 분리:** 최근 경기/목록에서 결과 상세로 들어갈 수 있고 수정은 별도 행동이다. 첫 구간만 펼치는 스쿼드·교체도 긴 스크롤을 줄인다.
- **정보의 정확성:** 0점과 미입력, 작성 중과 완료, 확인된 득실점 순서와 순서 미기록을 구별한다. 과거 기록에 없는 순서를 임의로 만들지 않는다.
- **상세 조회의 연속성:** 선수 기록의 조건을 선수 상세에 이어 적용하고, 목록 복귀 시 선택한 선수로 포커스를 돌려준다. 페이지 이동 시 결과 위치로 포커스/스크롤을 옮기는 코드도 있다.
- **선택적 공개:** 선수단 필터, 통계 경기 조건, 조회 기간 등 여러 설정이 이미 접기 구조다. 이번 개선은 이 장점을 유지하며 중복 영역을 합친다.
- **역할별 도움:** 운영진/회원 가이드와 PDF가 공통 원고를 사용한다. 가이드의 모바일 장 선택과 제목 포커스 이동이 있다.
- **접속 보호:** 팀 코드는 마스킹되고 재발급의 영향을 설명한다. 로그인 실패나 조회 실패에는 재시도 경로가 있다. 편의를 이유로 권한·비밀번호 정책을 약화할 필요는 없다.

## 후속 검토로 남길 항목

1. **목록 페이지 이동의 일관성.** 선수 기록은 새 페이지의 결과 위치로 이동하지만, 선수단·경기·대회는 페이지 상태만 바꾸는 경로다. `players/usePlayers.ts:38`, `PlayerDirectory.tsx:59–62`, `MatchSection.tsx:196–197`, `TournamentSection.tsx:64`. 실제 모바일에서 페이지 교체 뒤 위치가 불편한지 재현한 후, 결과 로딩 완료 시점에만 같은 포커스 규칙을 적용한다. 필터 타이핑마다 자동 스크롤하지 않는다.
2. **메뉴 전환 후 조회 조건 유지.** 화면을 벗어나면 구성 요소의 로컬 필터가 초기화될 수 있다. 공유 링크/뒤로가기까지 설계가 필요한 항목이므로 이번 시각적 압축과 섞지 않는다.
3. **실제 경기장 사용 점검.** 운영진 1명이 참석 선택→자동 배치→교체→득점→저장 흐름을 한 경기에서 써 보고, 막힌 위치와 반복 입력을 기록한다. 새로운 스탯·회원 정책은 그 결과를 보고 결정한다.
4. **용어 통일 점검.** “매칭/외부 경기”, “기록 완료/경기 완료”, “쿼터/전후반”은 화면 역할과 데이터 의미가 맞는지 계속 확인한다. 명칭만 일괄 치환해 서로 다른 의미를 지우지 않는다.

## 검증 및 배포 상태

- 수행: UX 코드 점검, 기존 가상 모바일 캡처 확인, 담당 로컬 변경의 `pnpm typecheck` 통과.
- 총괄 실측: 같은 가상 데이터의 390px 표 보기에서 첫 결과 행 위치 **1,390.30 → 837.20 CSS px**, 약 **39.8% 감소**. 첫 결과 위에 쌓인 높이를 비교한 것이며, 작업 시간·만족도가 40% 개선됐다는 뜻은 아니다.
- UI 측정 전달: 일부 주요 조작 영역 **36/32 → 44px**, soft 배경 위 텍스트 대비 **4.32:1 → 4.93:1**. 앱 전체 모든 요소의 접근성 인증을 뜻하지 않는다.
- 요약 SVG를 PNG로 렌더링해 전체 내용을 확인했다. 글자 겹침·잘림 없이 생성됐다. HTML은 반응형 텍스트 요약도 함께 제공한다.
- 남은 통합 검증 확정: 320/390px와 데스크톱 렌더, 긴 이름/대회명, 표/간단 보기, 0건/미입력/작성 중 경고, 보기 설정 조작, 홈 0건/작성 중 있음, 키보드 포커스. 총괄 결과를 받아 최종 반영한다.
- 사용자 가이드는 변경 문구·위치를 통합 확인한 뒤 갱신한다.
- **현재 이 개선은 로컬 작업 상태다.** 운영 배포 성공 및 운영 URL 검증 후 이 절을 확정한다.
